# 分段 84 — 成长值/等级后端化 + 个人资料页整幅图背景

> 用户反馈两点：
> 1. 个人资料页「去掉卡片，背景直接放图片，图片底部渐出」。
> 2. 「成长值接入后端，后端没有接口就自己补上去，别光补接口，还要补面板」。
>
> 此前 hero 的成长值是前端用 `points` 现算的假数据，本段把它落成后端真实字段 +
> 等级体系 + 管理台可编辑面板，并重做个人资料页视觉。

## 一、目标

- **成长值后端化**：新增 `User.growth` 列（累计、只增不减，与可消费的 `points` 分离），
  后端定义统一等级体系，提供查询接口；前端 hero / 个人资料页改用后端口径。
- **补管理台面板**：管理台「用户与角色」页可见并可编辑成长值（不止补接口）。
- **个人资料页重做**：去卡片，顶部整幅配图作背景、底部渐出融入页面，其上叠身份与成长值/等级。

## 二、后端改动

| 文件 | 改动 |
|---|---|
| `prisma/schema.prisma` | `User` 加 `growth Int @default(0)` |
| `prisma/migrations/20260616090000_add_user_growth/migration.sql` | `ALTER TABLE "t_user" ADD COLUMN "growth"`（手写迁移，`migrate deploy` 应用，兼容全新克隆） |
| `src/modules/platform/growth.js`（新增） | 等级阶梯 `GROWTH_LEVELS`（新芽/幼苗/拔节/抽穗/金穗/丰仓）+ `growthInfo(growth)` 推算等级/进度，**单一事实来源** |
| `src/modules/platform/user.controller.js` | `getProfile` 附带 `growthInfo`；新增 `getGrowth` |
| `src/modules/platform/platform.routes.js` | `GET /user/growth` |
| `src/modules/platform/resource.config.js` | 用户资源 `listFields` + `fields` 加 `growth`（成长值，int，可编辑） |
| `seeds/index.js` | `mkUser` 默认 `growth:0`；三位主角 demo 值 farmer 320 / bigfarmer 760 / village 1180 |

等级阶梯（min 为进入该级所需成长值）：

```
新芽 0 / 幼苗 100 / 拔节 300 / 抽穗 600 / 金穗 1000 / 丰仓 2000
```

`growthInfo` 返回：`{ growth, level, levelName, nextLevelName, currentLevelAt, nextLevelAt, remaining, progress, isMax }`。

> 管理台「用户与角色」是 `resource.config.js` 驱动的通用 CRUD 面板，列表/表单由配置自动渲染——
> 因此加一行 `field('growth', …)` 即同时获得**成长值列 + 可编辑表单项**，无需改管理台前端代码。

## 四、契约

| 路径 | 方法 | 用途 | 状态 |
|---|---|---|---|
| `/user/growth` | GET | 成长值与等级信息 | **本段新增** |
| `/user/profile` | GET | 个人资料，**新增** `growth` 字段 + `growthInfo` 对象 | 增强 |
| `/admin/resource/user/*` | CRUD | 成长值进入通用资源面板（列 + 可编辑 int 字段） | 增强 |

## 五、验收

- `npx prisma migrate deploy` 应用 `add_user_growth`；`prisma generate` 重生成 client。
- 后端 `node --check` 全过；`flutter analyze lib` → `No issues found!`；`flutter test` → 通过。
- 接口实测（farmer/张大叔，growth=320）：
  - `GET /user/growth` → `{level:3, levelName:'拔节', nextLevelName:'抽穗', remaining:280, progress:0.067 …}`
  - `GET /user/profile` → 含 `growth:320` 与同口径 `growthInfo`
  - `PUT /admin/resource/user/:id {growth:222}` → 写入成功（管理台编辑路径）
- 浏览器实测：
  - 我的页 hero：`张大叔` 旁 `Lv3 拔节` 胶囊 + `距抽穗还差 280 成长值` + 金穗色进度条（real 后端值）。
  - 个人资料页：整幅村庄荣誉配图背景、底部渐出、半透明返回钮、`成长值 320` + 进度条，字段无卡片直排；控制台 0 error。
  - 管理台「用户与角色」：新增**成长值**列（village 1180 / bigfarmer 760 / farmer 320），编辑表单含成长值输入项。

## 六、不在范围内

- 成长值的自动累加规则（哪些行为加多少分）暂不接入；本段只做字段 + 等级 + 展示 + 管理台手工调整。
- 等级阶梯为后端常量（业务规则），不做阶梯本身的 CRUD 面板。
- `points`（积分）口径不变，与 `growth` 分离。

## 七、实施备注

- 迁移用手写 SQL + `migrate deploy`（`migrate dev` 在非交互环境不可用）；DLL 占用导致 `prisma generate` EPERM，根因是 nodemon 守护的后端持有引擎，停整条 `npm run dev` 树后重生成再重启即可。
- 既有 demo 库的三位主角成长值通过一次性脚本回填（全新克隆走 seeds）。

## 八、个人资料页重构为「成长档案」（frontend-design 二改）

> 用户两次反馈「整幅人物配图叠白字」观感诡异，遂用 frontend-design 技能彻底重构。
> 根因：忙乱的志愿者 stock 照 + 叠白字 + 进度条是**通用 cover-photo 套路**，图字互相打架，
> 怎么调色都救不回来。决策：**弃用照片**，改用品牌自有材质构筑 hero。

只动 `app/lib/pages/profile/settings/account_page.dart`（数据/保存/成长值拉取逻辑不变）。

- **深绿 hero**：`#114F1C→#073A11` 渐变 + `_ContourPainter` 等高线纹理（7 条相位错开正弦线，
  白 5% 透明，农田地形隐喻，去「纯色扁平」），底部 `R.lg` 圆角落入浅背景。右上角淡麦金 `eco` 水印。
- **身份**：麦金描边圆头像（显示昵称首字「张」，无昵称回落 person 图标）+ 名字 + 麦金 `Lv3 拔节` 实心胶囊 + `角色 · 村庄`。
- **成长可视化（记忆点）**：大号麦金 `320 成长值` + `距抽穗还差 280` 文案 + `_LevelLadder`——
  作物成长六档阶梯（新芽/幼苗/拔节/抽穗/金穗/丰仓）：已过节点麦金实心、当前节点放大麦金+白环、
  未达暗白空心；当前→下一档的连接段按 `progress` 部分填充。一图说清「我在哪、还差多少、整条路」。
- **下方**：无卡片，按 `认证信息`（账号/角色只读）/ `个人资料`（4 个可编辑字段）分组，绿色字母间距 eyebrow 小标题 + 发丝分隔线。
- **动效**：`AnimationController` + `Interval` 错峰，hero 与各分段载入时淡入 + 轻微上移（克制、一次性）。

验收：`flutter analyze` 干净、`flutter test` 通过、`flutter build web` 成功；浏览器实测（farmer/张大叔 Lv3）
hero、阶梯（拔节高亮、抽穗段部分填充）、分组表单、保存按钮均正常，控制台 0 error。

> 取舍说明：照片被移除是有意决策（它正是「诡异」的根因）。若仍想要照片，可作为**可选**的
> 顶部窄幅 banner 回归，但不再做「整幅背景叠字」。
