# 111 · 登录/注册/重置密码硬性 BUG 修复（issues #23/#24/#25）

## 目标

处理用户在异机实测后提交的三条 GitHub issues（均为登录相关的硬性缺陷）：

- **#23 重置密码功能报废**：点「重置密码」没反应，网页和 APK 都一样。
- **#24 输入框校验串联**：只填了第一个输入框，下方的输入框全部开始飘红判定。
- **#25 登录相关页面间距过小**：登录 / 注册 / 找回密码页排布过挤。

## 背景

排查 `app/lib/pages/auth/` 三页（`login_page` / `register_page` / `forgot_password_page`）
与 `auth_widgets.dart`、`auth_state.dart`、后端 `platform/auth.controller.js` 后定位：

- **#24 根因（框架级确认）**：三页的 `Form` 都设了
  `autovalidateMode: AutovalidateMode.onUserInteraction`。该模式挂在 **Form 级**时，
  只要任意一个字段被输入过，Form 的 `_hasInteractedByUser` 即为 true，`Form.build`
  随后调用 `_validate()` **对全部字段一起校验**——于是「填第一个框、下面全部飘红」。

- **#23 有两层**：
  1. 直接原因（「点击没反应」）：`_resetPassword`/`_register` 里
     `if (!isValid) { setState(() => _error = null); return; }` ——校验不过时**静默返回**、
     不给任何顶部提示。叠加 #24 的全字段飘红，用户填完点按钮若某字段（手机号格式/两次密码）
     没过，就表现为「完全没反应」。
  2. 设计缺口：注册页只收「昵称 / 用户名 / 密码 / 确认」，**不收手机号**；仅当「用户名」
     本身是 11 位手机号格式时 `AuthState.register` 才顺带写 `phone`。而后端重置密码
     要求 `user.phone === 手机号`，导致**用文字用户名注册的账号 `phone` 为空、永远无法重置**。

- **#25**：`login` 字段间距 16、`register`/`forgot` 仅 12，`brandFormGap` 24 偏挤。

- 附带修一个静默 bug：前端注册发的是 `nickname` 字段，后端 `registerSchema` 只认
  `displayName` 且 `.strip()` 会丢弃未知键，导致**昵称一直被丢弃**、displayName 回退成用户名。

## 改动

1. **`app/lib/pages/auth/auth_widgets.dart`**
   - `AuthTextField` 新增 `autovalidateMode` 参数（默认 `onUserInteraction`），下沉到
     `TextFormField`：**每个字段只在自己被输入后校验自己**，不再连累其它字段。

2. **`login_page.dart` / `register_page.dart` / `forgot_password_page.dart`**
   - 移除 `Form` 级 `autovalidateMode: AutovalidateMode.onUserInteraction`（改由各字段独立校验）——修 #24。
   - `register` / `forgot` 字段间距 `12 → 16`，`brandFormGap 24 → 30`；`login` 密码框到协议行
     间距 `8 → 14`——修 #25。
   - `_resetPassword` / `_register` 校验不过时由静默返回改为顶部提示
     「请按提示补全上方信息后再重置密码 / 创建账号」——修 #23 的「没反应」。

3. **`register_page.dart`**（补 #23 设计缺口）
   - 新增「手机号（用于找回密码）」字段（`_phone` 控制器 + 11 位手机号校验 + 数字限长），
     提交时传给 `register`。

4. **`app/lib/core/auth_state.dart`**
   - `register(...)` 新增可选命名参数 `phone`；手机号来源优先显式字段、否则回退「用户名即手机号」。
   - 发送字段由 `nickname` 改为后端认可的 `displayName`（昵称从此真正生效）。

> 后端未改动：`/auth/reset-password` 路由、限流白名单、controller 逻辑本就正常。

## 契约

- `POST /api/v1/auth/register` 请求体：`{ username, password, displayName?, phone? }`
  （`phone` 为 11 位手机号；`displayName` 取代此前被丢弃的 `nickname`）。后端 schema 不变。
- `POST /api/v1/auth/reset-password` 契约不变：`{ username, phone, newPassword }`，
  需 `user.phone` 与传入手机号匹配。本次让新注册账号带上 `phone`，使其可被重置。
- 存量数据 / 登录 / 已有账号无影响；老账号若 `phone` 为空仍需管理台补录后才能自助重置。

## 实施备注

- #24 是 Flutter `Form` 级 `autovalidateMode.onUserInteraction` 的既知行为，标准修法即
  「不要挂在 Form 级」。下沉到字段级 `onUserInteraction` 既根治串联、又保留输入时即时提示。
- Flutter web CanvasKit 画布下 Playwright 坐标点击不稳（DPR/覆盖层），本次改用
  **开启无障碍语义树 → 操作真实 `<input>` + 表单回车提交**来做交互验证，稳定可复现。
- 换 bundle 后用 `?v=` 查询串 + `--pwa-strategy=none`（无 SW）规避 web 缓存跑旧代码。
