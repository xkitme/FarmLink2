# 113 Web 预览启动链修复

## 目标

修复 TripGo 风格重构后本地 Web 预览的严重启动报错与疑似白屏问题，保证 `scripts/start-local.ps1` 启动的 `http://localhost:5000` 能稳定展示移动端首页与个人中心。

## 根因

1. `flutter build web --pwa-strategy=none` 生成的 `flutter_service_worker.js` 为 0 字节，但 `flutter_bootstrap.js` 仍残留 `serviceWorkerSettings`，浏览器会等待 service worker 激活并抛出 `prepareServiceWorker took more than 4000ms` 警告。
2. `scripts/start-local.ps1` 之前用 `python -m http.server` 托管 `build/web`，绕过了项目自带 `serve_web.mjs` 的 Web 预览控制点，无法统一禁缓存与修补 bootstrap。
3. 用户当前浏览器可能已有旧 Flutter service worker 与 `flutter-*` CacheStorage，即使新包禁用 PWA，旧 SW 仍可能继续返回旧 `flutter_bootstrap.js`。
4. App 首屏初始化还被远程配置拖慢：语音唤醒词请求在 `VoiceWakeState.init()` 内被 `await`，启动广告接口沿用全局 15 秒超时，后端慢或未起时会放大为长时间加载。

## 改动

1. **Web 入口清理旧缓存**
   - `app/web/index.html`
   - 加载 Flutter 前先注销当前 origin 下的 service worker，并删除名称包含 `flutter` 的 CacheStorage。
   - 清理失败只打 `console.warn`，随后继续动态加载 `flutter_bootstrap.js`，避免清理逻辑本身阻断首屏。

2. **本地 Web 静态服务收口**
   - `app/serve_web.mjs`
   - 对 `index.html`、`flutter_bootstrap.js`、`main.dart.js`、`flutter_service_worker.js` 返回 `Cache-Control: no-store, max-age=0`。
   - 对外响应 `flutter_bootstrap.js` 时，将生成产物里的 `_flutter.loader.load({ serviceWorkerSettings: ... })` 改为 `_flutter.loader.load();`。
   - SPA fallback 同样 no-store，减少硬刷继续拿旧入口的概率。

3. **一键启动脚本改用项目 Web 服务**
   - `scripts/start-local.ps1`
   - 移除移动端 Web 预览对 Python 的依赖。
   - Web 预览改为在 `app/` 下启动 `node serve_web.mjs`，并在启动前设置 `$env:PORT = "$WebPort"`。

4. **首屏远程请求降级**
   - `app/lib/core/voice_wake.dart`
   - `refreshWakeWords()` 改为后台触发，不阻塞 `VoiceWakeState.init()` 和 App `_ready`。
   - `app/lib/pages/ad/startup_ad_page.dart`
   - `/site/startup-ad` 增加 2 秒局部超时，失败后直接进入 `/home`。

## 备注

- `GoRouter` 当前仍设置 `initialLocation: '/ad'` 与 `overridePlatformDefaultLocation: true`，所以硬刷新 `#/home` 或 `#/profile` 会先进入启动广告页，这是既有路由行为，不是本次 Web 启动错误。
- Flutter CanvasKit 已通过 `--no-web-resources-cdn` 自托管。Chrome 仍可能因字体 fallback 访问 Google Fonts，但本次白屏/严重报错根因已收口在 service worker 与首屏阻塞链路。
