## 目标

将 FarmLink 收敛为六条可完成的业务主路径，删除仅用于扩充数量、依赖模拟数据或与产品定位关系弱的页面、路由和接口，后续有真实需求与数据来源时再重新实现。

保留的六条主路径：

1. AI 植保：拍照识病、处置建议、农事记录。
2. 农产品交易：浏览商品、商品详情、下单、订单查询。
3. 农机服务：设备浏览、详情、预约、预约记录。
4. 防灾救助：预警、灾情上报、保险理赔、紧急求助。
5. 惠农政策：政策查询、政策问答、补贴申请、申请状态。
6. 村级经营：农情、交易、农机、灾情等经营数据看板。

AI 助手作为上述业务的统一问答、搜索和导航入口保留，不单独扩充功能数量。

## 删除范围

### Flutter App

- 删除乡村生活服务整板及其发布动态依赖。
- 删除模拟物联网设备与联动规则页面。
- 删除市场智能工具页：价格预测、期货、出口合规、收购地图、团购、质量分级、直播话术、包装文案、溯源与物流工具墙。
- 删除农机扩展服务页：维修、故障诊断、成本核算、轨迹、土地流转、认证与保险工具墙。
- 删除数据杂项服务页：年度报告、统计上报、同步日志等低频入口。
- 政策服务页只保留政策、补贴申请和政策问答。
- 精简功能目录、首页、搜索、个人中心、发布页和 AI 导航中的失效入口。
- 删除用户可见的功能数量卖点。

### Backend 与管理台

- 下线并删除 `life`、模拟 `iot` 业务模块及路由挂载。
- 删除市场、农机、政策、农业、防灾和数据模块中仅服务于上述非核心页面的模拟接口。
- 保留数据库既有表和迁移文件，避免破坏已有环境升级；不再从应用路由和管理台暴露对应资源。
- 清理 AI 助手功能词典、系统提示词、管理台菜单和 API 调试目录中的失效能力。

### 文档

- README、项目介绍和进度总览统一改为六条核心业务链路口径。
- 历史工作单作为开发记录保留，不再作为当前产品能力清单。

## 接口契约

- 保留六条主路径当前使用的接口和响应字段，不做无关协议重构。
- 被删除能力对应的接口不再挂载，访问时返回标准 404。
- 数据库 schema 本轮不删表、不改迁移，不对现有数据执行破坏性清理。

## 验收标准

- 首页与全部服务只展示六条主路径及其必要子任务，无生活服务、IoT 或智能工具墙入口。
- 全局搜索、个人中心、发布页和 AI 助手不会导航到已删除路由。
- Flutter 路由表不存在 `/life`、`/iot`、`/market/service`、`/machinery/service`、`/data/service`。
- 后端不再挂载 `/life`、`/iot` 及已删除的模拟业务接口。
- 代码库中不存在对应整页和整模块实现；数据库历史 schema 除外。
- `flutter analyze lib`、`flutter test`、Web build、后端语法检查及相关测试通过。
- 移动端与桌面宽度下：首页、全部服务和六条主路径无溢出、空白页或失效跳转。

## 不在范围内

- 不新增替代功能，不为了维持数量重新命名旧功能。
- 不重做认证、消息、设置、后台通用运维能力。
- 不删除数据库旧表、迁移和用户已有业务数据。
- 不接入新的第三方行情、金融或物联网数据源。
