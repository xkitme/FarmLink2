# 分段 45k — 主页「今日最重要的事」决策卡（视觉记忆点 D2）

> 工作单（Codex 实施）。所属 lane：[45-招牌场景与产品重构计划](45-招牌场景与产品重构计划.md) Lane D · D2。
> 进入首页第一眼就看到「平台在帮我做决定」。**复用现有接口，新增一次农事待办查询，并在数据看板聚合里补充最近政策截止项。**

## 一、目标

主页最顶（气象 strip 之上）加一张**今日决策卡**：按优先级算出「今天最重要的一件事」+ 一个大 CTA 直达处理。让首页从「功能入口堆」变成「平台主动给我建议」。

## 二、决策优先级（从高到低，命中即停）

| 优先级 | 条件 | 卡片文案 | CTA → |
|---|---|---|---|
| P1 | 有生效中的气象灾情预警（weather.alerts 非空） | ⚠「{alertLevel}：{title}」 | 查看防护 → `/disaster` |
| P2 | 未来 7 天有 `recordType` 含「复查」的排程 | ✅「待复查：{content}」 | 去复查 → `/agri` |
| P3 | 未来 7 天有打药/施肥/灌溉/采收/收获/播种/巡田排程 | 🌱「农事待办：{content}」 | 查看农事 → `/agri` |
| P4 | 有最近生效政策截止项 | 🏛「政策截止：{title}」 | 去办理 → `/policy/service` |
| P5 | 兜底（无事项） | ☀「今日天气{condition}，适宜农事」 | 看农情 → `/data` |

## 三、改动清单

### 1. `app/lib/pages/home/home_page.dart`

#### 3.1 `_load` 增加农事待办查询

现有 `_load` 已并行拉 weather / notification / life-help / queue（44a）。再加一项：

```dart
ApiClient.get('/agri/record/list', query: {'pageNum': 1, 'pageSize': 50}),
```

解析出「未来 7 天内 + 今天」的待办记录（recordDate 在 [今天, 今天+7天]，recordType 含「复查/打药/施肥/灌溉/采收/收获/播种/巡田」），存 `_todoRecords`。
单接口失败不阻塞（try/catch 包，失败则 `_todoRecords = []`）。

同时请求 `/data/dashboard`，读取 `upcomingPolicyDeadline`。单接口失败不阻塞，政策项缺失时继续使用天气兜底。

#### 3.2 决策计算

`_computeDecision()` 严格按第二节顺序命中即停。农事排程先按日期升序整理，再分别查找「复查」和一般农事，确保未来 7 天的待复查始终高于其他安排。四类事项都没有时，根据今日天气生成农情兜底。

#### 3.3 决策卡 widget（hero 风格，放 ListView 第一项）

决策卡使用实色背景：常规事项为品牌主绿，灾情预警为红/橙色；圆角使用 `R.lg`，阴影使用 `AppColors.ambientShadow`。CTA 满宽且最小高度 48px，使用 `R.sm` 圆角，不使用渐变或胶囊按钮。

#### 3.4 放进 ListView 第一项

```dart
ListView(
  children: [
    _decisionCard(),         // ← 新增，第一屏第一眼
    _weatherStripCard(),     // 气象 strip 下移
    const SectionTitle('核心服务', trailing: ...全部入口...),
    _serviceGrid(context),
    const SectionTitle('我的快讯'),
    _quickPanel(),
    const SectionTitle('未来天气趋势'),
    _forecastCard(),
  ],
);
```

### 2. 后端

不新增端点。复用 `/agri/record/list`、`/agri/weather`、`/data/dashboard`。

`backend/src/modules/data/dashboard.controller.js` 的既有聚合响应新增 `upcomingPolicyDeadline`：选择已生效且尚未截止的最近政策，仅返回 `id / title / category / validTo`，供首页展示政策截止 CTA。

> 确认 `/agri/record/list` 返回字段含 `recordType / content / recordDate`。45b 建档写入的「复查」「打药」记录会被这里读到，**与 45b 闭环联动**：张大叔拍照建档 7 天后复查 → 首页决策卡自动提示「待复查：黑星病防治效果复查」。

## 四、验收

1. `flutter analyze lib/pages/home` → No issues
2. 制造各优先级场景，决策卡正确切换：
   - 有预警 → 红卡「暴雨预警」→ 点击跳 /disaster
   - 无预警 + 未来 7 天有「复查」农事 → 绿卡「待复查：XX」→ 跳 /agri
   - 无复查 + 有一般农事排程 → 绿卡「农事待办：XX」→ 跳 /agri
   - 无农事排程 + 有政策截止 → 绿卡「政策截止：XX」→ 跳 /policy/service
   - 全空 → 兜底「今日天气晴，适宜农事」
3. **与 45b 联动验证**：用 45b 拍照建档（7 天后复查）→ 首页决策卡显示「待复查：黑星病防治效果复查」
4. 决策卡点击跳对应路由
5. `/agri/record/list` 失败 → 决策卡降级到政策截止或天气兜底，不崩

## 五、不在范围内

- 不做多事项轮播（只显示最高优先级一条）
- 不做"标记完成"交互（点 CTA 跳板块处理即可）
- 不新增推送
- 兜底文案不接天气以外的运势类内容
