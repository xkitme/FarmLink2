# 分段 43c — P2 修复

> 落地分段 42 review 清单的 P2 两项：G9 / G10。
> 本批处理通知刷新竞态与通知统计契约，不扩大到新产品能力。

## 一、目标

- 避免 ShellPage 首次进入时重复触发未读刷新。
- 避免通知未读刷新乱序响应覆盖较新的值。
- 清理通知列表 `typeCounts` 中的空类型污染，并让列表接口的 `unread` 与筛选类型保持一致。

## 二、实施备注

### G9 · 未读刷新去重与版本化

文件：

- `app/lib/core/notification_state.dart`
- `app/lib/pages/home/shell_page.dart`

处理：

- `NotificationState` 新增 `_refreshSeq`，每次 `refresh()` 递增序号。
- 接口返回后若不是最新序号，直接丢弃旧响应。
- 移除 `ShellPage.initState()` 中的首次刷新；首屏刷新由 `didChangeDependencies()` 统一触发，避免首次双请求。

### G10 · 通知类型统计契约清理

文件：`backend/src/modules/platform/notification.controller.js`

处理：

- `/notification/list` 的 `typeCounts` 在输出前过滤空 `type`。
- 列表接口的 `unread` 改为使用当前 `type` 筛选后的未读数；无 type 查询时仍为全局未读。

## 三、不在本批范围内

- 不新增通知类型。
- 不修改消息中心 UI 之外的通知业务流程。
- 不改 `/notification/unread` 的全局语义。

- `node --check backend/src/modules/platform/notification.controller.js`：通过。
