# 分段 45i — 数据汇总成「可讲数字」+ 首页规模徽章（内容故事化 C3）

> 工作单（Codex 实施）。所属 lane：[45-招牌场景与产品重构计划](45-招牌场景与产品重构计划.md) Lane C · C3。
> 让评委/用户进首页一眼看到平台规模：「已服务 N 户 / 覆盖 N 亩 / N 类作物 / N 条 AI 诊断 / N 单交易」。
> **复用 `/data/dashboard`，不新增端点；只加一个全平台口径聚合字段 + 首页一条徽章带。**

## 一、目标

把种子数据加总成「可对外念」的平台规模数字，做成首页一条横向徽章带（5 项），展示时直接念数字。

## 二、关键设计点（务必理解）

`/data/dashboard` 现有 `cards` 是**按角色行级过滤**的（农户只看自己的 totalAreaMu/aiCallCount/作物类）。
「可讲数字」是**对外展示平台规模**，必须**全平台口径、与登录角色无关**（农户登录看到的也是平台总量）。
因此**新增一个独立字段 `platformStats`，全部用不带 user/region 过滤的查询**，与现有 `cards` 并存、互不影响。

## 三、改动清单

### 1. 后端 `backend/src/modules/data/dashboard.controller.js`

在 `dashboard()` 里新增一组**全平台**聚合（不带 `userWhere/plotWhere/regionWhere`），追加到响应 `platformStats` 字段。**不要动现有 `cards` 的角色口径。**

字段（全平台）：
| 字段 | 含义 | 取数 |
|---|---|---|
| `farmerCount` | 服务农户 | `prisma.user.count()`（现有 `userCount` 已是全平台，可直接复用，不必重复查） |
| `totalAreaMu` | 覆盖耕地（亩） | 全部 `landPlot.areaMu` 求和（**不带 plotWhere**，单独查一次全量 `areaMu`） |
| `cropTypeCount` | 服务作物（类） | 全部 landPlot 的 distinct `cropType` 数（空/未填写不计） |
| `aiServiceCount` | AI 诊断（条） | `aiQaRecord.count()` + `aiDetectRecord.count()`（**不带 userId 过滤**，全平台） |
| `orderCount` | 交易（单） | `prisma.order.count()`（现有已是全平台，可复用） |

实施要点：
- 复用已有的全平台查询结果（`userCount`、`orderCount` 本就是 `.count()` 无过滤），**新增的只有**：全量 plots 的 `areaMu`/`cropType`（可单独 `findMany({ select:{areaMu:true,cropType:true} })` 全量，或 `groupBy`）、以及不带 userId 的 ai 计数。
- 把这几项放进 `Promise.all`，最后在 `ok(res, { ... })` 里加 `platformStats: { farmerCount, totalAreaMu, cropTypeCount, aiServiceCount, orderCount }`。
- 数字 `toFixed(2)` 口径与现有 `totalAreaMu` 一致；count 类取整。
- **不新增端点**，就挂在 `/data/dashboard` 响应里。

### 2. 前端 `app/lib/pages/home/home_page.dart`

#### 2.1 取数（复用现有 /data/dashboard 调用）

现有 `_loadUpcomingPolicyDeadline()`（约 115 行）已经 `ApiClient.get('/data/dashboard')` 只取了 `upcomingPolicyDeadline`。
**改造它一次取两样**（避免重复打接口）：返回一个 `{policy, stats}` 或新增并行项都行，但**优先复用这一次请求**——读出 `data['platformStats']` 存到状态 `Map<String,dynamic>? _platformStats`。
单接口失败：`_platformStats = null`（徽章带隐藏），不影响其它块。

> 推荐做法：把 `_loadUpcomingPolicyDeadline` 改成 `_loadDashboardExtras`，返回 `{'policy':..., 'stats':...}`，在 `_load` 的 `results[2]` 里一次性解析出 `_upcomingPolicyDeadline` 和 `_platformStats`。保持 Future.wait 项数不变。

#### 2.2 徽章带 widget `_platformStatsStrip()`

- 放在 **ListView 顺序：问候+天气 → 今日决策卡 → 〔可讲数字带〕 → 核心服务**（即 `_decisionCard()` 之后、`SectionTitle('核心服务')` 之前）。
- 横向一排 5 个 stat（窄屏可横滑 `SingleChildScrollView(scrollDirection: Axis.horizontal)` 或自适应 Wrap，不溢出）：
  - 🧑‍🌾 服务农户 `{farmerCount}` 户
  - 🌾 覆盖耕地 `{totalAreaMu}` 亩
  - 🌱 服务作物 `{cropTypeCount}` 类
  - 🔬 AI 诊断 `{aiServiceCount}` 条
  - 🛒 累计交易 `{orderCount}` 单
- 视觉（Agro-Modernist Tech，**审美在线**）：大号粗体数字（主绿 `AppColors.primary` 或麦金 `AppColors.gold` 系）+ 小灰标签；卡片 `R.md` 圆角、`AppColors.ambientShadow` 柔阴影或细描边。**禁** generic 渐变 / 半透明白浮层 / 脉冲光 / 大圆角胶囊。可参考现有 `data_dashboard_page.dart` 的 `_smallStat`/`_pill` 风格。
- `_platformStats == null` 或全 0 → **整条不渲染**（`if (_platformStats != null) _platformStatsStrip()`），不显示占位 0。

#### 2.3 文案口径

按 `docs/进度总览.md` 产品呈现约定：纯展示平台服务规模，**不出现「离线 / 本地 / 单机 / 兜底」等词**。用「服务 / 覆盖 / 累计」中性词。
