# 106 · 语音助手回复逻辑重构（前答案残留 / 一问两答 彻底根除）

## 目标
用户要求**重构**而非继续打补丁。两个必须结构性消除的现象：
1. 上一轮 AI 回答仍残留在回复框；
2. 先输出一个答案、又被第二个答案替换。

## 根因（为何补丁治不好）
回复框 `_replyMarkdown` 是单字段、跨轮持有；旧逻辑在一轮内**多次**写它：先写模型 `replyMarkdown`、再被命令（`show_message`/`create_order`/`show_order_confirm`/`mock_pay`）或回声二轮覆盖 → 「先一个又被替换」。提交新一轮时也不清空 → 「上次答案还留着」。TTS `speakAndWait` 依赖引擎「播放完成」回调，模拟器上该回调不可靠：不触发→等到 15s 超时（麦克风留守、识别不到说话），或提前触发→开麦时 TTS 还在响（回声二次回答）。

## 重构（改 `voice_assistant_layer.dart` + `tts_service.dart`）
**回复装配改为「一轮一答、只写一次」**：
- `_submitRecognized`：确认提交即 `_replyMarkdown=''`、`_hasReply=false`——上轮答案立刻消失；上轮文案作为 `lastReply` 上下文传后端后即清。错误分支也置 `_hasReply=true` 让错误成为该轮答案。
- `_executeCommand`：`show_order_confirm`/`create_order`/`mock_pay`/`show_message` 不再就地写 `_replyMarkdown`，改为在返回值里带 `reply` 文案。
- `_executeCommands`：收集各命令的 `reply` 覆盖文案并返回列表，不在执行途中显示。
- `_applyAssistantResponse`：先执行命令，再决定**唯一**答案 = 命令覆盖（取最后一条）否则模型 `replyMarkdown`，**只 setState 一次** `_replyMarkdown` 并 `_hasReply=true`，随后只朗读这一条。
- 覆盖层回复气泡仅在 `_hasReply && 文案非空` 时显示（去掉 `||_sending`），处理中不露旧答案。

**TTS 等待改为「预估时长、可打断、不空等」**：
- `speakAndWait` 不再 await 引擎完成回调，改按文本长度预估播放时长（中文 ~240ms/字，clamp 900ms~30s）轮询等待，每 80ms 检查 `_seq` 是否被打断。等待窗口=朗读时长：可预期、可被 barge-in 打断、不会因回调缺失空等到 15s（治「麦克风留守→识别不到」）；朗读期间麦克风保持关闭（治回声）。

## 契约
不改后端接口/命令白名单。命令返回值新增可选 `reply` 字段（仅前端内部用）。

## 验收
- `flutter analyze`（两文件）→ No issues found。
- 需 APK 复验：一条指令只出**一个**答案、不被替换；新指令前回复框先清空；朗读完很快回到「聆听中…」、不再十几秒无反应。

## 不在范围 / 后续
- 「第一次（助手未朗读时）就识别不到」若仍存在 → 模拟器未把真麦克风音频喂给 sherpa（开 "Virtual microphone uses host audio input" 或真机）。
- 回声仍由静默窗 + 文本判别兜底；如设备仍偶发，退路是朗读后改点按再聆听。
