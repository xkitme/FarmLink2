# 产品呈现口径

> 田园通对外定位为一套**在线 SaaS 数字乡村平台**。
> 离线只是底层运行方式的一种实现细节，不构成产品卖点，**不在用户可见层面强调**。
> 本文件统一文案口径，所有界面、提示、对外文档须按此撰写。

## 一、原则

1. 把项目当成一个**正式在线服务**做：用户感知到的是「云端平台」。
2. 离线能力是内部技术实现，写在 README「技术架构」一节即可，**不向用户暴露**。
3. 任何「离线 / 断网 / 本地兜底 / 单机 / 本地模型」类术语，在 UI、Toast、空状态、引导页、
   宣传图、应用商店介绍、产品帮助里**一律禁用**。
4. 错误统一以「服务侧」口径呈现，不要把责任归到「网络」或「本地」。

## 三、可保留的术语

- 「数据同步」「同步队列」「待发送 / 已发送」—— 中性词，可用
- 「云端」「平台」「服务」—— 推荐
- 「AI 助手」「AI 识别」「AI 问答」—— 推荐，**不要带「本地」前缀**
- 「实时」「在线」—— 可用，但不要强调反义

## 四、内部 vs 对外

| 层 | 是否可提离线 |
|---|---|
| 用户 UI / Toast / 空状态 / 引导页 | ❌ 禁止 |
| 应用商店介绍 / 宣传材料 | ❌ 禁止 |
| 用户帮助中心 / FAQ | ❌ 禁止（避免主动暴露） |
| README「项目简介 / 核心特点」 | ⚠️ 弱化，可写「弹性部署」「可在内网/外网均可运行」 |
| README「技术架构」一节 | ✅ 可写（技术实现细节） |
| docs/ 内部分段文档 | ✅ 可写（开发记录） |
| 后端日志 / 错误详情 | ✅ 可写（运维诊断） |

## 五、技术说明口径（同样不提"离线"二字）

**核心规则**：对外（用户、客户、验收方、宣传）一律按「在线 SaaS 平台」讲。
后端不依赖外网这件事，**说法是「私有化部署 / 内网部署能力」**，不是「离线」。

| ❌ 错误说法（不要用） | ✅ 正确说法 |
|---|---|
| 「我们是离线优先的平台」 | 「我们是一个在线 SaaS 平台」 |
| 「断网也能用」 | 「支持私有化部署 / 内网部署 / 单机部署」 |
| 「本地 AI 兜底」 | 「内置 AI 引擎，无需依赖外部 API」 |
| 「临时要求所以做了离线」 | （根本不提这种话） |
| 「Ollama 本地模型」 | 「平台自研 AI 引擎」或「本地化 AI 推理」 |
| 「断网照常记录、联网回放」 | 「数据安全冗余 / 自动重传保障」 |

**验收方问到时怎么答**：

> Q：你们的部署形态？
> A：在线 SaaS 平台，标准 Web/App 接入。同时支持私有化部署到客户内网 ——
> 数据库、AI 推理、业务后端全栈本地化，特别适合数据敏感的乡镇政府场景。

> Q：AI 模型怎么部署？
> A：平台内置 AI 引擎，本地化推理。问答 / 视觉识别 / 向量检索三类模型在本机
> RTX 5060 可跑，不依赖任何外部 API 服务。

> Q：网络中断会怎样？
> A：平台具备完整的数据冗余与自动重传机制 —— 客户端缓存、增量同步、冲突检测
> 都是产品标配能力。

「离线」「断网」「本地 AI 兜底」这些词 **在技术说明里也不出现**。把同一件事换成产品力的语言。

## 七、生效
