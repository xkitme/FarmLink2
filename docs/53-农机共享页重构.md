# 分段 53 — 农机共享页重构

> 工作单（并行实施）。所属：板块体验优化（55+ 路线，承接 50/51/52 布局收尾）。
> 用户已认方向：把 `/machinery` 从「地图占满 + 底部单卡」改成「地图收小 + 真实农机列表 + 真实预约表单」，
> 并补「发布农机」入口。**复用现有接口，不新增、不改后端。**
>
> 完成后跑 `flutter analyze lib`，commit 中文。**视觉重写改动 → commit 前等用户点头。**

## 一、目标（一句话）

进 `/machinery`：顶部能**真搜 + 真筛**，中部地图**收到 1/3 屏并标注"即将上线"**，
下部是**可滚动的真实农机列表（3~4 张/屏）**，点卡片**真实选日期下单**，右上能**发布自己的农机**。

## 二、背景

现状 `app/lib/pages/machinery/machinery_page.dart`：

1. **搜索栏是假的** —— 一个不可点的占位 Container，没有 `TextField`、没有跳转。
2. **筛选写死且对不上数据** —— 硬编码 `['附近可用','大型拖拉机','联合收割机','无人机']`，
   `case 3` 查询 `machineType='无人机'`，但 seed 里实际类型是 **`植保机`**，永远查不到（拖拉机/收割机能命中纯属巧合）。
   seed 真实类型：**拖拉机 / 收割机 / 插秧机 / 植保机**（见 `backend/seeds/index.js`）。
3. **布局是地图独占** —— 整屏 `Stack`（背景图当地图）+ 浮动 marker + 底部**只有一张**选中卡，
   一屏看不到几台农机，"丰满感"为零；地图又是静态图（无真实地图能力）。
4. **预约是假流程** —— 「立即预约」直接写死 `明天-后天`，无选日期、无金额预览。
5. **无发布入口** —— 后端 `POST /machinery` 早已就绪，但 App 端没有任何发布农机的 UI。
6. service 页（`machinery_service_page.dart`）7 项工具已全部联通后端，**逻辑不缺**，只是排布不够"工具墙"。

## 四、Lane K · 搜索 + 筛选数据驱动（machinery_page 顶部）

### K1 · 真搜索框

把现有不可点的 `_searchBar()` 占位换成可输入的 `TextField`（或可点开搜索的 `TextField`）：

- 受控 `TextEditingController _keyword`，`onSubmitted` / 右侧搜索按钮触发 `_loadMachines()`。
- 关键字走**前端本地过滤**已加载列表的 `machineName` / `machineType`（后端 list 无 keyword 参数，**不要新增后端参数**）。
- 样式保持 Agro-Modernist：圆角 999 胶囊、`AppColors.surface`、`AppColors.ambientShadow`，禁纯黑阴影/渐变。
- 右侧 `tune` 圆钮保留为装饰即可（本段不做高级筛选面板）。

### K2 · 筛选 chip 数据驱动

把写死的 `_filters` + `_machineTypeQuery` 的 `switch` 改为**从真实数据派生**：

- 进页先拉一次全量 `GET /machinery/list?pageSize=50`，对返回 `records` 的 `machineType` **取 distinct** 得到类型集合。
- chip 列表 = `['全部', ...distinctTypes]`（首项「全部」= 不传 `machineType`）。
- 选中某类型 → 以 `machineType=<该类型原值>` 重新查（**原值直传，不再硬编码映射**），这样 `植保机` 等都能命中。
- 选中态视觉沿用现有 `_filterRow()`（`AppColors.primary` 填充 / 描边）。

> 验收点：seed 数据下，chip 至少出现「全部 / 拖拉机 / 收割机 / 插秧机 / 植保机」，点「植保机」能筛出「植保无人机」。

## 五、Lane L · 农机列表 + 真实预约（machinery_page 中下部）

### L1 · 地图收到 1/3 屏 + "即将上线"角标

- **不要删地图**。把现有背景图 + marker 那块从「整屏 Stack」收成一个**固定高度区块**（屏高的 1/3 ~ 2/5，约 220~260px），圆角 `R.md` 包裹。
- 右上角叠一个小角标 chip：`地图功能即将上线`（用 `StatusChip` 或半透明小药丸，文案中性，**不得**出现「离线/本地」字样，遵守 `docs/产品呈现口径.md`）。
- marker 可保留少量装饰性点位即可，**不再承担"选中某台"职责**（选中改由下方列表卡承担）。
- 用户后期会接真实离线地图包，所以**保留**这块容器与背景图引用，仅收高度。

### L2 · 真实农机列表（3~4 张/屏）

地图区块**下方**改为可滚动的农机卡列表（`ListView` / `Column`，外层页面整体可滚动）：

- 每张卡尺寸收敛到一屏能看到 **3~4 张**（横向布局：左缩略图 ~84px + 右信息），不要再用现在那种占大半屏的巨卡。
- 卡内字段（全部来自 `_Machine.fromApi`，**已有**）：名称、类型、`￥{price}/天`、评分、押金、机主、距离。
- 点整卡 → 打开 **L3 预约 sheet**（不再是底部常驻单卡）。
- 空状态：`AppCard` 文案「附近暂无可租农机」；加载用现有 `Loading`；`_fromCache` 时保留 `AlertBanner('农机数据更新中…')`。

### L3 · 真实预约表单 sheet

把写死 `明天-后天` 的 `_bookMachine` 换成**选日期 + 金额预览**的弹层：

- `showModalBottomSheet`，**必须 `useRootNavigator: true`**（项目硬约定，底栏要被遮）。
- 表单字段：
  - 起租日期 / 归还日期 → 用 `showDatePicker`（中文 locale 已配）选，默认起=明天、止=后天。
  - 实时算 `天数 = 止-起+1`、`预计租金 = price × 天数`、显示 `押金 ￥{deposit}`。
  - 备注（选填）`TextField`。
- 提交调**已有** `POST /machinery/booking`：
  ```
  { machineryId, startDate:'YYYY-MM-DD', endDate:'YYYY-MM-DD', remark }
  → data: { ..., days, totalAmount, deposit }，msg「预约已提交，等待机主确认」
  ```
- 成功后 `toast` 用后端返回 msg（或「预约已提交，等待机主确认」），关闭 sheet。
- 失败：`toast(context, actionErrorMessage('预约', error), error: true)`，sheet 不强关。
- `machine.id == null`（fallback 占位）时禁用提交并提示「农机资料更新中，请稍后预约」。

## 七、接口契约（全部已存在，禁止新增/改后端）

| 用途 | 方法 路径 | 入参 | 出参要点 |
|---|---|---|---|
| 农机列表 | `GET /machinery/list` | `pageNum,pageSize,machineType?,regionCode?,onlyAvailable=1` | `{records[], total}`；`machineType` 精确匹配 |
| 我的农机 | `GET /machinery/mine` | — | `[{id,machineName,machineType,...}]` |
| 农机详情 | `GET /machinery/:id` | — | `{...,owner:{nickname,villageName,phone}}` |
| **发布农机** | `POST /machinery` | `{machineName*,machineType,dailyPrice,deposit,description,images?}` | msg「农机已发布」 |
| **预约** | `POST /machinery/booking` | `{machineryId,startDate,endDate,remark}` | `{days,totalAmount,deposit}`，msg「预约已提交，等待机主确认」 |

> 注：`startDate/endDate` 后端 `new Date()` 解析，传 `YYYY-MM-DD` 即可；不能预约自己的农机（后端会 400，前端可不预判）。
