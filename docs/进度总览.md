## 技术约束（交付要求）

- 强制离线部署，完整项目包可独立运行
- 全部后端功能部署在本机
- 轻量数据库（SQLite）
- 不用 Docker
- AI 功能必须有，本地模型
- 管理面板功能丰富：数据增删改查、API 开关、API 在线调试

## 产品呈现约定

- 所有界面、文档和交付说明按普通正式成品口径撰写。
- 不在产品内暴露临时开发背景；功能命名以真实业务为准。
- **对外定位：在线 SaaS 平台**。所有文案、UI、提示一律按「云端在线服务」口径撰写，
  不要出现「离线优先」「断网可用」「本地兜底」「离线兜底」「本地 AI」「单机部署」等强调离线属性的词。
  - 错误码 60002（离线降级）对用户提示：`服务暂时不可用，请稍后重试`，不要写「已切换离线」
  - 同步队列对用户提示：`已加入待发送队列，将自动重传`，不要写「已存本地，联网后回放」
  - AI 兜底对用户：`正在处理中`，不要写「使用本地知识库兜底」
  - 缓存兜底对用户：直接展示数据，不要顶 banner 写「当前为本地缓存」
- 离线能力仅作为内部技术实现保留，写在内部 docs / README 的「技术架构」一节即可，
  不在产品 UI、对外宣传、用户帮助文案中出现。

## 业务范围

- 6 条核心业务链路：AI 植保 / 农产品交易 / 农机服务 / 防灾救助 / 惠农政策 / 村级经营
- AI 助手统一承载问答、搜索和核心业务导航
- 历史数据库结构兼容保留，不以数据表和入口数量作为产品规模口径
- 后端核心业务包：agri / market / machinery / disaster / policy / data / ai / platform
