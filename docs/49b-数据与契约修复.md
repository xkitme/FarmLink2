## H6 · migrate-thread-id 脚本无事务 / 无重试 / 无断点续传

### 现状

49a 启动钩子已经缓解此问题（每次启动 idempotent 跑），但 `backend/scripts/migrate-thread-id.js` 独立脚本仍是串行 N 次 update，10k 行慢且无错误恢复。

### 改动

把 `backend/src/startup/migrate-thread-id.js` 改用一次性 rawSQL：

```js
import { prisma } from '../db.js'

export async function migrateThreadIds() {
  try {
    // 先 count 知道要迁移多少
    const pending = await prisma.aiQaRecord.count({
      where: { threadId: null },
    })
    if (pending === 0) return 0

    // 一次性 SQL UPDATE（SQLite 与 PostgreSQL 都支持 column self-reference）
    const result = await prisma.$executeRawUnsafe(
      `UPDATE t_ai_qa_record SET thread_id = id WHERE thread_id IS NULL`
    )
    return result  // 受影响行数
  } catch (e) {
    console.warn('迁移 AI 记录 threadId 失败:', e.message)
    return 0
  }
}
```

`backend/scripts/migrate-thread-id.js` 已经在 49a 改为复用启动钩子，自动跟上。

### 验收

1. 制造 1000 条 `threadId IS NULL` 的 AiQaRecord（一次性 SQL insert）
2. 重启后端 → 启动日志 `✓ 迁移 1000 条 AI 记录 threadId` 1 秒内完成
3. 数据库 `SELECT COUNT(*) FROM t_ai_qa_record WHERE thread_id IS NULL` → 0

## H7 · DELETE /ai/qa/records/:id 语义改变未升版

### 现状

`backend/src/modules/ai/ai.controller.js:qaRemove` 现在删除目标 record 所在的**整个 thread**。这与旧契约「删一条」不兼容；管理台或外部脚本按旧契约调用会意外清掉一整段对话。

### 改动

#### 7.1 拆分两个独立路径

```js
// 删一条 record（保留 thread 其它消息）
export async function qaRemoveOne(req, res) {
  const id = Number(req.params.id)
  if (!Number.isInteger(id) || id <= 0) throw errors.param('id 不合法')
  const baseWhere = req.user.role === 'ADMIN' ? {} : { userId: req.user.id }
  const result = await prisma.aiQaRecord.deleteMany({
    where: { ...baseWhere, id },
  })
  if (result.count === 0) throw errors.notFound('记录不存在')
  ok(res, { id, deleted: result.count }, '已删除单条')
}

// 删整 thread
export async function qaRemoveThread(req, res) {
  const threadId = Number(req.params.threadId)
  if (!Number.isInteger(threadId) || threadId <= 0) throw errors.param('threadId 不合法')
  const baseWhere = req.user.role === 'ADMIN' ? {} : { userId: req.user.id }
  // 兼容未迁移行：threadId IS NULL AND id = threadId
  const result = await prisma.aiQaRecord.deleteMany({
    where: {
      ...baseWhere,
      OR: [
        { threadId },
        { id: threadId, threadId: null },
      ],
    },
  })
  if (result.count === 0) throw errors.notFound('对话不存在')
  ok(res, { threadId, deleted: result.count }, `已删除整段对话（${result.count} 条）`)
}
```

#### 7.2 `ai.routes.js` 路由

```js
router.delete('/ai/qa/records/:id',       wrap(ai.qaRemoveOne))      // 单条
router.delete('/ai/qa/threads/:threadId', wrap(ai.qaRemoveThread))   // 整 thread
```

#### 7.3 前端 `ai_chat_page.dart` 删除按钮改调 thread 接口

`_deleteCurrentThread` 现状调 `DELETE /ai/qa/records/$id` —— 改为：

```dart
await ApiClient.delete('/ai/qa/threads/$_threadId');
```

#### 7.4 兼容旧客户端

保留 `qaRemove` 旧 handler 一段时间，但加 deprecation 日志：

```js
export async function qaRemove(req, res) {
  console.warn(`[DEPRECATED] DELETE /ai/qa/records/:id 语义改变，请改用 DELETE /ai/qa/threads/:threadId（请求 from user=${req.user.id}）`)
  return qaRemoveThread(req, { params: { threadId: req.params.id } }, ...) // 转发到 thread 删除
}
```

> Codex 注：上面写法不对，路由不能直接调 handler。简化做法：保留 `qaRemove` 作为 alias，内部走 `qaRemoveThread` 逻辑 + 加 warning log。

#### 7.5 `apiCatalog.js` / API 文档更新

记录两个端点的语义差异。

### 验收

1. DELETE `/ai/qa/records/5` → 仅删 id=5 一条（如果 thread 还有别的 record，刷新仍能看到）
2. DELETE `/ai/qa/threads/5` → 删除 threadId=5 全部 records
3. 前端 ai_chat_page 删除按钮 → 整 thread 消失
4. 旧客户端继续 DELETE `/ai/qa/records/X` → 仍删整 thread（兼容）+ 后端 console 出现 deprecation warning

## H8 · qaRecords 内存分页性能

### 现状

`qaRecords` 不带 skip/take findMany 全表读，然后内存 groupBy + slice。重度用户 / ADMIN 时一次几 MB JSON 解析阻塞事件循环。

### 改动

#### 8.1 用 rawSQL 做 GROUP BY 聚合

```js
export async function qaRecords(req, res) {
  const { pageNum = 1, pageSize = 20 } = req.query
  const limit = Math.min(Number(pageSize) || 20, 100)
  const offset = (Math.max(Number(pageNum) || 1, 1) - 1) * limit
  const userScope = req.user.role === 'ADMIN' ? '' : `WHERE user_id = ${Number(req.user.id)}`

  // 拿 thread 摘要：threadId、首条 id、首条 createdAt、计数
  const summaries = await prisma.$queryRawUnsafe(`
    SELECT
      COALESCE(thread_id, id) AS threadId,
      MIN(id) AS firstRecordId,
      MIN(created_at) AS firstCreatedAt,
      MAX(created_at) AS lastCreatedAt,
      COUNT(*) AS messageCount
    FROM t_ai_qa_record
    ${userScope}
    GROUP BY COALESCE(thread_id, id)
    ORDER BY MAX(created_at) DESC
    LIMIT ${limit} OFFSET ${offset}
  `)

  // 用 firstRecordId 拉首条记录细节（用于 preview）
  const ids = summaries.map((s) => Number(s.firstRecordId))
  const records = ids.length === 0 ? [] : await prisma.aiQaRecord.findMany({
    where: { id: { in: ids } },
    select: { id: true, scene: true, question: true, answer: true, createdAt: true, referencesJson: true },
  })
  const recordMap = new Map(records.map((r) => [r.id, r]))

  // 总 thread 数（分页 total）
  const totalRow = await prisma.$queryRawUnsafe(`
    SELECT COUNT(DISTINCT COALESCE(thread_id, id)) AS total FROM t_ai_qa_record ${userScope}
  `)
  const total = Number(totalRow[0]?.total || 0)

  const threads = summaries.map((s) => {
    const head = recordMap.get(Number(s.firstRecordId))
    return {
      id: Number(s.firstRecordId),
      threadId: Number(s.threadId),
      messageCount: Number(s.messageCount),
      scene: head?.scene || 'GENERAL',
      question: head?.question || '',
      answer: head?.answer || '',
      referencesJson: head?.referencesJson || null,
      createdAt: s.lastCreatedAt,
    }
  })

  okPage(res, { records: threads, total, pageNum: Number(pageNum) || 1, pageSize: limit })
}
```

> Codex 注：rawSQL 的字段名需要匹配 prisma `@map("t_ai_qa_record")` 后的实际列名（snake_case）。具体列名可能是 `id / user_id / thread_id / scene / question / answer / created_at / references_json`。实施前先 `npx prisma format` 看一下，或 `SELECT * FROM sqlite_master WHERE type='table' AND name='t_ai_qa_record'` 确认列名。

#### 8.2 前端 `ai_threads_page.dart` 适配

后端响应字段名可能轻微变化，前端 `_load` 解析时确保兼容：

```dart
final list = (data['records'] as List? ?? [])
  .map((r) => _Thread(
    id: r['id'] ?? r['threadId'],
    title: ...,
    preview: r['answer'] ?? '',
    messageCount: r['messageCount'] ?? 1,
    ...
  )).toList();
```

### 验收

1. 制造 5000 条 AiQaRecord（脚本生成）
2. ADMIN 进 AI 历史 → 一次响应时间 < 100ms（原本 5s+）
3. 列表正常分页（pageNum=2 看下一页）
4. thread 计数显示正确
