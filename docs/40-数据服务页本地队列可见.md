# 分段 40 — 数据服务页接入本地待发送队列

> 闭环分段 38 F6 修复：让客户端 `OfflineSyncQueue` 保留的 `lastError` 真正可见。
> 数据管理服务页同步卡 + 同步日志 sheet 显式展示本地队列与诊断信息。
> `flutter analyze lib` 全绿。

## 背景

F6 把 `lastError` 从硬编码 `'同步失败'` 改为 `'$e'`（原始异常字符串），但 App
之前没有任何界面读取这个字段，等于「保留了，没人看」。本分段把它接入用户/运维
可见路径，闭环这一改动。

## 实现

### 1. _load 并行读取本地队列

```dart
final results = await Future.wait<dynamic>([
  ApiClient.get('/data/annual-report/list', ...),
  ApiClient.get('/data/statistics', ...),
  ApiClient.get('/data/statistics/summary'),
  ApiClient.get('/data/sync/status'),
  OfflineSyncQueue.all(),     // ← 新增
]);
_localQueue = results[4] as List<SyncQueueItem>;
```

后端失败的 catch 分支也单独拉一次 `OfflineSyncQueue.all()`，保证断网时本地队列
依然能看到。

### 2. 同步卡显示「待发送」+「立即同步」

mini stat 改为 4 列：**待发送 / 总计 / 成功 / 失败**（合并 conflict + failed
为「失败」一列，简化展示）。

当 `waiting > 0` 时，卡片右上角按钮从「查看全部」切换为「立即同步」
（FilledButton.tonalIcon，带 loading），调用新增的 `_flushQueue()`：

```dart
Future<void> _flushQueue() async {
  final result = await OfflineSyncQueue.flush();
  toast(context,
      result.total == 0
          ? '待发送队列暂无数据'
          : '已处理 ${result.total} 条，成功 ${result.success} / 冲突 ${result.conflict} / 失败 ${result.failed}');
  await _load();
}
```

底部补一个「查看本地队列与全部日志」次级入口。

### 3. _SyncLogsSheet 增加 SERVER / LOCAL 切换

`_SyncLogsSheet` 接收 3 个新参数：`localQueue` / `onFlush` / `flushing`。
顶部 ChoiceChip 切换：

- **服务端日志**：原有 `/data/sync/logs` 分页 + 状态筛选
- **本地队列**（label 后缀显示数量徽标 `· N`）：渲染 `widget.localQueue` 数组

每条本地队列 tile 展示：

```
[农事记录]                                              [待重试]
INSERT · 入队 11-26 14:32 · 重试 2 次
TimeoutException after 0:00:30.000000: ...
```

`lastError` 用 status 对应色显示，最多 3 行 ellipsis。

LOCAL tab 顶部还有「立即同步」按钮（与卡片一致），同步成功 sheet 关闭后外层
`_load()` 再跑一次，刷新视图。

## 用户视角

- **同步顺利**：同步卡显示「待发送 0 / 总计 N / 成功 N / 失败 0」，按钮是「查看全部」
- **有数据待发**：mini stat 显示橙色「待发送 3」，按钮变蓝「立即同步」，点击批量推送
- **诊断失败原因**：「本地队列」tab 中每条都展示具体 `lastError`（如 timeout / 422 / 5xx）
  ——这是 F6 改进的真实落点
