# 分段 43b — P1 修复

> 落地分段 42 review 清单的 P1 五项：G4 / G5 / G6 / G7 / G8。
> 本批只处理数据一致性与运行时卡死风险，不开启分段 45 的新功能。

## 一、目标

- 管理台初始化数据中心只保留一个权威总记录数，避免分组汇总与总览口径打架。
- 消息中心分类数字使用后端返回的全局统计，列表支持继续加载。
- 数据服务页在缓存或队列读取失败时也能退出 loading。
- 登录成功后立即刷新底栏未读数。
- 数据同步卡在服务数据更新中时，用明确占位区分本机待发送队列与平台同步统计。

## 二、实施备注

### G4 · 初始化数据统计口径一致

文件：

- `backend/src/modules/platform/admin.controller.js`
- `backend/admin/src/pages/SeedDataPage.jsx`

处理：

- 后端 `seedDataSummary()` 不再向每个 group 返回 `totalCount`。
- 管理台“板块数据概览”移除“记录数”列。
- 总览卡继续以 `summary.recordCount` 作为唯一权威记录数。

### G5 · 消息中心计数改用后端统计

文件：`app/lib/pages/messages/messages_page.dart`

处理：

- `_load()` 只请求 `/notification/list?pageNum=1&pageSize=100`，直接消费响应中的 `total`、`unread`、`typeCounts`。
- 分类 chip 计数改为：
  - 全部：后端 `total`
  - 未读：后端 `unread`
  - 类型：后端 `typeCounts`
- 列表保留客户端筛选，并新增“加载更多”按钮，逐页追加数据，避免 chip 统计只代表首屏窗口。
- 全部已读、打开消息后的刷新统一走 `_reload()`，同步更新 `NotificationState`。

### G6 · 数据服务页兜底加载不再卡死

文件：`app/lib/pages/data/data_service_page.dart`

处理：

- `_load()` 的 catch 分支对 `OfflineCache.readList()` 和 `OfflineSyncQueue.all()` 再包一层 try/catch。
- 即使缓存或队列读取异常，也会进入最终 `setState()`，把 `_loading` 置为 `false` 并展示服务提示。

### G7 · 登录后刷新底栏未读

文件：`app/lib/core/auth_state.dart`

处理：

- `_save()` 写入 token 与用户信息后，调用 `NotificationState.refresh()`。
- 登录 / 注册成功后底栏消息徽标会立即刷新，不再等 ShellPage 路由变化。

### G8 · 同步卡拆分本机队列与平台统计语义

文件：`app/lib/pages/data/data_service_page.dart`

处理：

- `_syncCard()` 在 `_error != null && _syncStatus.isEmpty` 时，将“总计 / 成功 / 失败”显示为 `—`。
- “待发送”仍然来自 `OfflineSyncQueue`，可继续查看和重传。
- 错误态提示改为“服务数据更新中，待发送队列可继续查看”，不再出现“待发送 N / 总计 0”的矛盾。
