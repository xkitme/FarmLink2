## H1 · passwordChangedAt @default(now()) 让所有现有 token 升级即被踢

### 现状

`backend/prisma/schema.prisma` 加：

```prisma
passwordChangedAt   DateTime @default(now())
```

`prisma db push` 在 SQLite 上把所有 existing user 的 `passwordChangedAt` 都设为「push 那一刻」的时间戳。

`backend/src/middleware/auth.js` 的 fallback 路径：

```js
if (!decoded.pwdAt && user.passwordChangedAt) {
  if (decoded.iat * 1000 < user.passwordChangedAt.getTime() - 1000) {
    throw errors.unauthorized('密码已修改，请重新登录')
  }
}
```

**所有升级前签发的 token**（无 `pwdAt` 字段，iat 早于部署时刻）都会命中此分支被撤销。即使用户从未改过密。

### 改动

#### 1.1 改 schema 默认值

`backend/prisma/schema.prisma`：

```prisma
// 改前
passwordChangedAt   DateTime @default(now())

// 改后（推荐方案 A）
passwordChangedAt   DateTime?
```

或方案 B：保留 `@default(now())`，但在 prisma db push 之后立刻跑一次回填脚本，把所有 user 的 passwordChangedAt 设为他们各自的 `createdAt`（更准确：他们的 createdAt 一定早于任何 in-flight token，所以 fallback 会正常通过）。

**推荐方案 A**（DateTime?）—— null 值意味着「从未改过密」，fallback 跳过校验。

#### 1.2 auth.js 校验逻辑改

```js
// 改前
if (user.passwordChangedAt &&
    decoded.iat * 1000 < user.passwordChangedAt.getTime() - 1000) {
  throw errors.unauthorized('密码已修改，请重新登录')
}

// 改后
if (user.passwordChangedAt) {
  const pwdMs = user.passwordChangedAt.getTime()
  // 严格匹配 pwdAt（新版 token）
  if (decoded.pwdAt !== undefined) {
    if (Number(decoded.pwdAt) !== pwdMs) {
      throw errors.unauthorized('密码已修改，请重新登录')
    }
  } else {
    // fallback：旧 token 无 pwdAt 字段，比较 iat
    if (decoded.iat * 1000 < pwdMs - 1000) {
      throw errors.unauthorized('密码已修改，请重新登录')
    }
  }
}
```

#### 1.3 updatePassword 写 timestamp

`backend/src/modules/platform/user.controller.js:updatePassword`：

```js
await prisma.user.update({
  where: { id: req.user.id },
  data: {
    passwordHash: newHash,
    passwordChangedAt: new Date(),
  },
})
```

仍然写当前时间。

#### 1.4 跑 migration

```powershell
cd backend
npx prisma db push
npx prisma generate
```

### 验收

1. 升级 schema 后，**完全不动密码**，用旧 token 调任意 `/api/v1/*` 接口 → **200**（不再 401）
2. PUT /user/password 修改密码 → 旧 token 调接口 → 401「密码已修改，请重新登录」
3. 用新密码登录拿新 token T2 → 调接口 → 200

## H2 · qaThreadRecords 严格 threadId 匹配，未迁移行 404

### 现状

`backend/src/modules/ai/ai.controller.js:235`：

```js
export async function qaThreadRecords(req, res) {
  const threadId = Number(req.params.threadId)
  const records = await prisma.aiQaRecord.findMany({
    where: { threadId, ...(isAdmin ? {} : { userId: req.user.id }) },
    orderBy: { createdAt: 'asc' },
  })
  if (records.length === 0) throw errors.notFound('对话不存在')
  ok(res, { records })
}
```

未迁移的旧 AiQaRecord（`threadId IS NULL`）查不到。

`qaRecords` 列表分组里前端 `t.threadId = row.threadId || row.id` 兜底；用户点进未迁移 thread → 404。

### 改动

```js
export async function qaThreadRecords(req, res) {
  const threadId = Number(req.params.threadId)
  if (!Number.isInteger(threadId) || threadId <= 0) {
    throw errors.param('threadId 不合法')
  }
  const baseWhere = req.user.role === 'ADMIN' ? {} : { userId: req.user.id }
  // 兼容未迁移行：threadId == id 视为同一 thread
  const records = await prisma.aiQaRecord.findMany({
    where: {
      ...baseWhere,
      OR: [
        { threadId },
        { id: threadId, threadId: null },   // 未迁移的旧 record
      ],
    },
    orderBy: { createdAt: 'asc' },
  })
  if (records.length === 0) throw errors.notFound('对话不存在')
  ok(res, { records })
}
```

### 验收

1. 跑 `migrate-thread-id.js` 之前的库：用 GET /ai/qa/threads/{某旧 record.id} → 返回该单条 record（200）
2. 跑迁移之后：同接口返回该 thread 全部 records
3. 不存在的 threadId（如 99999）→ 404

## H3 · qaRemove deleteMany 对未迁移行 0 删假成功

### 现状

```js
export async function qaRemove(req, res) {
  const id = Number(req.params.id)
  const row = await prisma.aiQaRecord.findFirst({
    where: { OR: [{ id }, { threadId: id }], userId: req.user.id },
  })
  if (!row) throw errors.notFound('记录不存在')
  await prisma.aiQaRecord.deleteMany({
    where: { threadId: row.threadId ?? id, userId: req.user.id },
  })
  ok(res, { id }, '已删除')
}
```

`row.threadId ?? id` 在未迁移行（row.threadId=null）会退到 `id`，但实际行的 threadId 仍是 null，deleteMany 命中 0 行。**返回 ok 但数据未删**。

### 改动

```js
export async function qaRemove(req, res) {
  const id = Number(req.params.id)
  if (!Number.isInteger(id) || id <= 0) throw errors.param('id 不合法')
  const baseWhere = req.user.role === 'ADMIN' ? {} : { userId: req.user.id }
  const row = await prisma.aiQaRecord.findFirst({
    where: { ...baseWhere, OR: [{ id }, { threadId: id }] },
  })
  if (!row) throw errors.notFound('记录不存在')
  // 兼容未迁移行：threadId 为 null 时按 id 删
  const result = row.threadId != null
    ? await prisma.aiQaRecord.deleteMany({
        where: { ...baseWhere, threadId: row.threadId },
      })
    : await prisma.aiQaRecord.deleteMany({
        where: { ...baseWhere, OR: [{ id: row.id }, { threadId: row.id }] },
      })
  if (result.count === 0) throw errors.notFound('未找到要删除的记录')
  ok(res, { id, deleted: result.count }, `已删除 ${result.count} 条`)
}
```

### 验收

1. 未迁移行（threadId=null）DELETE /ai/qa/records/:id → 200，`deleted: 1`，刷新列表该行消失
2. 已迁移 thread（含 3 条 records）DELETE 其中任一 id → 200，`deleted: 3`，整 thread 消失
3. 不存在的 id → 404

```js
  ...
}
```

`backend/src/startup/migrate-thread-id.js`：

```js
import { prisma } from '../db.js'

export async function migrateThreadIds() {
  try {
    const rows = await prisma.aiQaRecord.findMany({
      where: { threadId: null },
      select: { id: true },
    })
    if (rows.length === 0) return 0
    let success = 0
    for (const r of rows) {
      try {
        await prisma.aiQaRecord.update({
          where: { id: r.id },
          data: { threadId: r.id },
        })
        success++
      } catch (e) {
        console.warn(`迁移 record ${r.id} 失败: ${e.message}`)
      }
    }
    return success
  } catch (e) {
    console.warn('迁移 threadId 启动钩子失败:', e.message)
    return 0
  }
}
```

每次启动时 idempotent 跑，残留行自动补齐。同步把 `backend/scripts/migrate-thread-id.js` 改为只调用该函数：

```js
import { migrateThreadIds } from '../src/startup/migrate-thread-id.js'
const n = await migrateThreadIds()
console.log(`迁移完成：${n} 条`)
process.exit(0)
```
