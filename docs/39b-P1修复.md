# 分段 39b — P1 修复

## F4 · 失败时重置 summary / syncStatus

**文件**：`app/lib/pages/data/data_service_page.dart`

`_load()` 失败时只重置了 `_annualReports` / `_statRecords`（从缓存读回），
但 `_statSummary` 与 `_syncStatus` 保留了上次成功的值，造成头部数字与列表内容不一致。

**改动**：catch 内 setState 追加两行：

```dart
_statSummary = {};
_syncStatus = {};
```

注释同步更新：「summary/status 失败时清零，不缓存」，与 F4 修复后行为一致。

## F5 · 抽 _StatFormSheet，释放 controller

**文件**：`app/lib/pages/data/data_service_page.dart`

原 `_openStatForm` 在函数闭包内 new 5 个 `TextEditingController`，bottom sheet
关闭后没有 dispose。反复开关 sheet 会持续泄漏。

**改动**：

1. 新增 `_StatFormData` 类承载表单结果（statType / year / period / cropType / areaMu / yieldKg）。
2. 新增 `_StatFormSheet` StatefulWidget，5 个 controller + `_year` 字段放 State，
   `dispose()` 中逐个释放。
3. `_openStatForm` 简化为：

```dart
final result = await showModalBottomSheet<_StatFormData>(
  context: context,
  isScrollControlled: true,
  ...
  builder: (_) => const _StatFormSheet(),
);
if (result == null || !mounted) return;
await ApiClient.post('/data/statistics/report', body: { ... });
```

4. 把原 state class 内的 `_field` 抽成顶层私有函数 `_formField(...)`，
   两边复用，避免代码重复。`_StatFormSheet` 内 `setState` 直接刷新选中年份。

## F6 · 队列 lastError 保留原异常

**文件**：`app/lib/core/offline_sync_queue.dart`

原 `_submit` 返回 `SyncStatus`，调用方在 SUCCESS 以外都写入硬编码 `'同步失败'`，
catch 块 `catch (_)` 直接吞掉原始异常 —— 同步日志看不到真实失败原因。

**改动**：

1. 引入 `_SubmitResult { status, detail? }` 替代裸 `SyncStatus`：

```dart
class _SubmitResult {
  final SyncStatus status;
  final String? detail;
  const _SubmitResult(this.status, [this.detail]);
}
```

2. `_submit` 解析后端返回的 `results[0].detail` 并塞进 `_SubmitResult`，
   覆盖 SUCCESS / CONFLICT / FAILED 三态。

3. `flush()` 循环：
   - conflict 分支：`lastError: result.detail ?? '服务端数据更新，需要人工合并'`
   - failed 分支：`lastError: result.detail ?? '同步失败'`
   - **catch 改为 `catch (e)`**：`lastError: '$e'`，把 timeout / 5xx / parse 等
     原始异常字符串保留到队列项。

用户层提示文案不动（同步状态卡仍走中性词），诊断信息只在 `SyncQueueItem.lastError`
内沉淀，可在数据管理服务页的同步日志详情 sheet 中显示。
