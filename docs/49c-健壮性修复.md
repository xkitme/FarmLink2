## H9 · ApiClient.stream 无行缓冲，跨 chunk 切包导致 done 帧丢失

### 现状

`app/lib/core/api_client.dart:84`：

```dart
static Stream<String> stream(String path, Map<String, dynamic> body) async* {
  ...
  await for (final chunk in res.stream.transform(utf8.decoder)) {
    for (final line in chunk.split('\n')) {
      if (line.startsWith('data: ')) {
        final d = line.substring(6).trim();
        if (d == '[DONE]') return;
        yield d;
      }
    }
  }
}
```

- 只识别 `data: ` 行，event 名（`event: done` / `event: meta`）被丢
- 按 chunk 边界 split('\n')，跨 chunk 的多行 data 会被截断
- 后端 `sse(res, 'done', {recordId, threadId, ...})` 在 chunk 不幸切包时 done 帧不完整 → JSON 解析失败 → threadId 永远拿不到 → 新对话首发后 `_threadId` 留 null → 追问开新 thread

### 改动

重写 stream 解析为**行缓冲 + event 路由**：

```dart
class SseEvent {
  final String type;        // 'message' / 'done' / 'meta' / ...
  final dynamic data;       // 解析后的 JSON 或 原始字符串
  const SseEvent({required this.type, this.data});
}

static Stream<SseEvent> streamEvents(String path, Map<String, dynamic> body) async* {
  final req = http.Request('POST', _uri(path))
    ..headers.addAll(_headers)
    ..body = jsonEncode(body);
  final res = await req.send().timeout(const Duration(seconds: 12));
  if (res.statusCode != 200) throw ApiException(res.statusCode, '请求失败');

  String buffer = '';
  String? eventName;

  await for (final chunk in res.stream.transform(utf8.decoder)) {
    buffer += chunk;
    while (true) {
      final idx = buffer.indexOf('\n');
      if (idx < 0) break;
      final line = buffer.substring(0, idx);
      buffer = buffer.substring(idx + 1);

      if (line.isEmpty) {
        // event 终结符 \n\n 在 split 后表现为空行；reset eventName
        eventName = null;
        continue;
      }
      if (line.startsWith('event: ')) {
        eventName = line.substring(7).trim();
        continue;
      }
      if (line.startsWith('data: ')) {
        final raw = line.substring(6);
        if (raw == '[DONE]') return;
        dynamic parsed;
        try {
          parsed = jsonDecode(raw);
        } catch (_) {
          parsed = raw;
        }
        yield SseEvent(type: eventName ?? 'message', data: parsed);
      }
      // 其它字段（id:, retry:）忽略
    }
  }
}

/// 旧 API 保持兼容：把 data 中的 delta 抽出来 yield String
static Stream<String> stream(String path, Map<String, dynamic> body) async* {
  await for (final event in streamEvents(path, body)) {
    if (event.type == 'message' && event.data is Map) {
      final delta = (event.data as Map)['delta'];
      if (delta is String) yield delta;
    } else if (event.type == 'done') {
      return;
    }
  }
}
```

## H10 · 1s 容差同会话改密绕过

### 现状

`backend/src/middleware/auth.js:25`：

```js
function tokenChangedBeforePassword(decoded, user) {
  if (!user.passwordChangedAt || !decoded.iat) return false
  return decoded.iat * 1000 < user.passwordChangedAt.getTime() - 1000
}
```

同会话内（10:00:00 登录 + 10:00:00.500 改密）：
- iat = 10:00:00（秒精度）→ iat * 1000 = 10:00:00.000
- passwordChangedAt = 10:00:00.500
- 10:00:00.000 < 10:00:00.500 - 1000 = 9:59:59.500 → **不成立**，旧 token 仍可用

### 改动

#### 10.1 移除 1s 容差，改严格小于

```js
function tokenChangedBeforePassword(decoded, user) {
  if (!user.passwordChangedAt || !decoded.iat) return false
  // 移除 -1000 容差：iat 秒级精度，passwordChangedAt 毫秒级
  // 任何「iat 时刻早于 passwordChangedAt」都应撤销
  return decoded.iat * 1000 < user.passwordChangedAt.getTime()
}
```

#### 10.2 fallback 路径优先级降低

对**已知有 pwdAt 字段的新版 token**，永远走严格匹配（不进 fallback）。tokenPasswordSnapshotStale 已经按这个写。无需改。

但**完全无 pwdAt 的旧 token** 在新版 client 上不该再存在（49a 部署后所有 signToken 都写 pwdAt）。如果想更严格，可以把 fallback 改为「直接撤销所有无 pwdAt 的 token」，强制所有用户在 49c 部署后重登。

**本工作单选保守方案**：保留 fallback 但移除 1s 容差。如果未来发现仍有边缘绕过，再改强制重登。

### 验收

1. 用户 A 登录拿 T1（iat=10:00:00）
2. A 在同会话内立即调 `PUT /user/password`，passwordChangedAt 写入 10:00:00.500
3. A 用 T1（旧 token）再调任意接口 → 401「密码已修改，请重新登录」

## H11 · 49a H1 升级路径 data residual（review 第二轮新发现）

### 现状

49a 把 `User.passwordChangedAt` schema 改为 `DateTime?`，但 48a 跑过的 `prisma db push` 已经把所有 existing user 的这一列填为 T_48a 时间戳；schema 改 nullable 不会清空 existing 数据。

结果：
- 48a 之前签发的旧 token（iat < T_48a）→ fallback 路径 `iat * 1000 < T_48a - 1000` → 撤销
- 即使该用户从未改过密

49a 工作单验收 1「完全不动密码用旧 token → 200」仅在 fresh install / fresh seed 场景成立。

### 改动

#### 11.1 启动钩子追加 passwordChangedAt 残留清理

`backend/src/startup/migrate-thread-id.js` 改名 / 拆分为多个启动迁移；或者新建 `backend/src/startup/clean-default-pwd-changed-at.js`：

```js
import { prisma } from '../db.js'

/**
 * 清理 48a 部署时 prisma @default(now()) 留下的残留 timestamp。
 * 启发式判定：所有 user 的 passwordChangedAt 都是同一时间戳，且该时间戳早于
 * 第一次合法改密操作 → 大概率是 48a 部署残留，全部置 null。
 *
 * 这是 idempotent 的清理：跑过一次后，后续改密会写入真实时间戳，启发式不再命中。
 */
export async function cleanDefaultPwdChangedAt() {
  try {
    const users = await prisma.user.findMany({
      where: { passwordChangedAt: { not: null } },
      select: { id: true, passwordChangedAt: true, createdAt: true },
    })
    if (users.length === 0) return 0

    // 启发式：如果 passwordChangedAt 与 createdAt 相差极小（< 1 分钟）
    // 且 passwordChangedAt 与所有其他 user 的 passwordChangedAt 高度集中
    // → 判定为 prisma default 残留
    const groups = new Map()
    for (const u of users) {
      const minute = Math.floor(u.passwordChangedAt.getTime() / 60000)
      groups.set(minute, (groups.get(minute) || 0) + 1)
    }
    // 如果 80%+ user 落在同一分钟内 → 残留
    const maxBucket = Math.max(...groups.values())
    if (maxBucket / users.length < 0.8) return 0   // 不像残留，跳过

    const dominantMinute = [...groups.entries()]
      .find(([_, n]) => n === maxBucket)?.[0]
    const lo = dominantMinute * 60000
    const hi = lo + 60000

    const result = await prisma.user.updateMany({
      where: {
        passwordChangedAt: {
          gte: new Date(lo),
          lt: new Date(hi),
        },
      },
      data: { passwordChangedAt: null },
    })
    return result.count
  } catch (e) {
    console.warn('清理 passwordChangedAt 残留失败:', e.message)
    return 0
  }
}
```

> 启发式 80% 阈值是为了避免误杀真实改密事件。生产数据如果一天内只有 1-2 个真实改密，加上一波 48a 残留，残留肯定占多数，会被正确清理。

### 验收

1. 模拟场景：把所有 user.passwordChangedAt 手动设为同一时间戳（模拟 48a push）
2. 重启后端 → 启动日志 `✓ 清理 N 条 48a 残留 passwordChangedAt`
3. user.passwordChangedAt 全部变 null
4. 旧 token（48a 前签发，无 pwdAt）→ tokenPasswordSnapshotStale 因 user.passwordChangedAt = null 直接 return false → 200
5. 用户改密后写入新时间戳 → 启发式不再命中（不会被清掉）→ 旧 token 被正确撤销

## H12 · migrate-thread-id 串行 N 次 update 阻塞 boot（review 第二轮）

### 现状

`backend/src/startup/migrate-thread-id.js` 串行 `for...of + await update`，10k 条要数十秒。

### 改动

改用 rawSQL 一次性 UPDATE（与 49b H6 一致）：

```js
export async function migrateThreadIds() {
  try {
    const pending = await prisma.aiQaRecord.count({
      where: { threadId: null },
    })
    if (pending === 0) return 0
    await prisma.$executeRawUnsafe(
      `UPDATE t_ai_qa_record SET thread_id = id WHERE thread_id IS NULL`
    )
    return pending
  } catch (e) {
    console.warn('迁移 AI 记录 threadId 启动钩子失败:', e.message)
    return 0
  }
}
```
