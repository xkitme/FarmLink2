# 103 · 语音助手功能点全覆盖 + 回答去重（治「接入不完全 / 第二个答案」）

## 目标
1. **功能点接入不完全**：语音助手「很多自带功能都不认识」——说「实时行情 / 农事日历 / 交水电费 / 农机故障 / 我的订单」等细粒度功能时，助手答不上来或打不开。
2. **AI 输出后又生成第二个答案**：一次语音指令，AI 先出一个回答，紧接着又被另一段回答覆盖（看起来像答了两次）。

## 背景
- doc101 的 `open_page` 只把 **35 个静态页面**（首页/集市/农机/政策…）喂给模型（`ROUTE_CATALOG`）。
- 但 App 端 `app/lib/core/feature_catalog.dart` 列了 **69 个功能点**（实时行情、农事日历、补贴申请、村医问诊、水电气缴费、灾情上报、农机故障诊断、遥感分析、溯源码…），每个功能点都归属于某个已存在的页面路由。
- 这 69 个功能点**从未喂给语音助手模型**，所以用户说功能点名时，模型在它仅有的 35 个页面名里找不到对应 → 「不认识」。**所有 feature_catalog 的 route 都能映射回助手现有 routeKey，前端 `_routePaths` 已全部支持**，因此只需把功能点喂给模型即可，无需新增路由。
- 第二个答案的根因：`voice_assistant_layer.dart` 的 `_executeCommands` 在执行完任意命令后，会再调一次 `/ai/assistant/command-result` 跑**第二轮 LLM**，其回复**覆盖**第一轮的 `_replyMarkdown`。doc102 已把「播报」收敛为只播最终一次，但**气泡文案仍被第二轮覆盖**，用户视觉上仍是「答了两次」。而语音操作最常见的就是导航（`open_page`），每次都会触发这第二轮——本次新增的功能点映射又让几乎所有功能指令都产出 `open_page`，二者叠加会让「第二个答案」更频繁，故必须一并去除。

## 改动
### 后端（功能点喂给模型）
- `backend/src/modules/ai/services/assistant.service.js`
  - 新增 `ROUTE_FEATURES` 映射（routeKey → 该页承载的功能点中文别名数组，与 `feature_catalog.dart` 对齐，含口语别名如「交水电费/水费电费」「农机故障/农机维修」「查快递/订单状态」）。
  - `buildUserPrompt` 的 `availableRoutes` 每项附上 `features` 数组。
- `backend/src/modules/ai/services/assistant-config.service.js`
  - `DEFAULT_SYSTEM_PROMPT` 新增规则 7：availableRoutes 带 features 功能点清单，用户说出任意功能点名时打开其所属页面，只要能对应到页面就不要回「不支持/没有这个功能」。

### 前端（去除第二个答案）
- `app/lib/widgets/voice_assistant_layer.dart`
  - `_executeCommands`：**移除**执行命令后回传 `/ai/assistant/command-result` 触发第二轮 LLM 的整段逻辑，只按序执行命令。事务类命令（`create_order`/`mock_pay`）已在 `_executeCommand` 内就地写好结果文案，反馈足够。
  - 删除随之失效的 `_commandResultDepth` 字段及其在 `_deactivate` 的重置。
  - `_applyAssistantResponse` 去掉只剩默认值的 `speakAfterCommands` 参数，回复 + 单次播报逻辑保持不变。

## 契约
- `/ai/assistant/turn` 响应结构不变：`{ replyMarkdown, speakText, statusText, commands[], modelUsed, serviceMode }`。
- `/ai/assistant/command-result` 端点**保留**（后端未删），只是 App 不再调用它。
- `open_page` 命令 routeKey 取值集合不变（仍是 `ALLOWED_ROUTE_KEYS`）；本次只是让模型「更会选对 routeKey」。
