# 分段 45 — 招牌场景与产品重构计划（总览）

> 这是一份**项目级 reposition plan**，不是单一工作单。
> 目的：把 FarmLink 从「76 模块功能列表」变成「30 秒记得住 + 1 个农户故事」的成熟成品。
> 落地路径：本文件先列 5 个 lane × 共 15 个子任务，按优先级排，后续按需展开成各自的
> `docs/45a-*.md` / `45b-*.md` / ... 工作单交 Codex 实施。

## 一、根因诊断

为什么这个项目让人觉得"普通"，不是单一原因：

| # | 根因 | 致命度 |
|---|---|---|
| R1 | **定位散，没有招牌场景** —— 想覆盖一切，没有让人复述的"明星功能" | ★★★★★ |
| R2 | **故事弱，数据是占位级** —— 没有「张大叔的一年」这种主角剧本 | ★★★★★ |
| R3 | **门面薄，76 模块藏在 3-4 层下**，能露脸的 ≈ 20 个 | ★★★★ |
| R4 | **差异化不够锐** —— 「在线 SaaS + 私有化部署」是真技术力，但产品 / 技术说明里都没用产品力语言讲出来（参见 `docs/产品呈现口径.md` 第五节） | ★★★★ |
| R5 | **没让人"哇"的瞬间** —— 无签名级交互、无可记忆画面、无可吹数字 | ★★★ |

**结论**：单加几个功能或改几张卡解决不了。要按 lane 同步推进。

## 二、目标

让 FarmLink 在用户 / 产品展示 / 技术说明三个语境里**都有一句话能复述**：

- 用户语境：「拍一张叶子，30 秒后 AI 给我农药剂量 + 自动记账 + 7 天后提醒复查」
- 产品展示语境：「一个农户 + 一个村委 + 一个 AI，全链条数字化乡村」
- 技术语境：「在线 SaaS 平台，全栈支持私有化部署到乡镇内网；内置 AI 引擎本地推理；76 模块端到端」

> ⚠️ 技术语境**不出现「离线 / 断网 / 本地 AI 兜底 / 临时要求」**这类词，
> 一律按 `docs/产品呈现口径.md` 第五节的产品力语言来。

## 三、5 个 Lane（共 15 个子任务）

> Lane 内子任务按优先级排序；每个任务对应一份独立的 docs 工作单（待 Claude 后续展开）。

### Lane A · 招牌场景（产品级差异化）

让用户记住「这个 App 能做什么」。

| 编号 | 任务 | 工作单 | 优先级 | demo 价值 |
|---|---|---|---|---|
| A1 | **拍照一键全闭环** —— 拍叶片 → AI 识病 → 农药+剂量 → 自动农事记录 → 7 天提醒复查 | 待写 `45b` | ★★★★★ | demo 高光镜头之一 |
| A2 | **村级数字驾驶舱大屏** —— 公开 H5 链接，全屏滚动该村农情/灾情/政策/集市实时数据 | 待写 `45c` | ★★★★★ | demo 高光镜头之二 |
| A3 | **AI 月度经营报告** —— 每月 1 号自动生成农户上月成本/收入/亩产对比 + 政策提示，推送 + 可导 PDF | 待后续编号 | ★★★★ | 让用户感觉"平台在帮我管账" |

### Lane D · 视觉记忆点（解 R5 无"哇"瞬间）

## 五、不在这份 plan 范围内

- **不重做底层架构**（路由 / state / 后端模块 / DB schema 都不动）
- **不强加 React Native / 换技术栈**
- **不堆新功能** —— 76 已经够多了，这份 plan 全是「让现有 76 被看见 + 串成故事 + 展示讲得出」
- **不改产品口径** —— 部署能力只在技术说明里讲，UI/对外仍按 `产品呈现口径.md` 写

## 九、判断标准

1. "这个 App 帮农户做什么？" → 答得出（A1 闭环故事 + C1 主角）
2. "这个项目有多大？" → 一屏看见 76 个（B2 工具墙 + B1 搜索）

现在三个都答不上来 = 普通。三个都答得上来 = 不普通。
