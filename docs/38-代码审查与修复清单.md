## 三、修复清单

### P0 · 必修（运行时风险 / 用户损失）

#### F1. `app/lib/pages/data/data_service_page.dart:71` — setState after dispose

- **现象**：`_load()` 的 catch 在 `if (!mounted) return;` 之后还有两个 `OfflineCache.readList` await，然后 setState 没有再次检查 mounted。
- **触发**：用户断网打开页面 → Future.wait 抛错 → cache 读取期间用户点返回 → setState 在已 dispose 的 State 上执行 → Flutter 抛 'setState() called after dispose()'。
- **修复**：catch 内每个 await 后都补 `if (!mounted) return;`，或把两次 readList 提到 setState 同一帧之前。
- **附带检查**：同文件 `_generateAnnualReport` / `_openStatForm` / `_openSyncLogs` 也走一遍同 pattern。

#### F2. `app/lib/pages/machinery/machinery_page.dart:554` — 占位农机仍可点「立即预约」

- **现象**：`onPressed: _booking ? null : () => _bookMachine(machine)`，去掉了原先 `machine.id == null` 的 guard。`_bookMachine` 仍然在 id 为空时 toast 后返回，但按钮视觉上一直可点。
- **触发**：首次启动或后端不可达 → 渲染内置 `_fallback` 农机（id == null） → 用户反复点击「立即预约」 → 每次只看到 toast「农机资料更新中」，无 loading 反馈，怀疑应用故障。
- **修复**：
  - onPressed 改回 `(_booking || machine.id == null) ? null : () => _bookMachine(machine)`
  - 卡片底部增加「资料更新中 / 暂未上架」小字标签（用 `StatusChip` + `outline` 色）
  - `_fallback` 中的真实型号「雷沃欧豹 M1004」改为「示例农机 · 资料更新中」

#### F3. `app/lib/pages/market/market_page.dart:678` — 占位商品的「加入合计」假成功

- **现象**：`_showProductDetail` 弹层里 `加入合计` 按钮无条件 `Navigator.pop` + `_addCart(product)`。`_addCart` 在 id == null 时只 toast 不入车。
- **触发**：后端不可达 → 渲染 `_fallback` 商品（id == null） → 用户在 detail 里点「加入合计」→ sheet 关闭（造成成功假象）→ 一闪而过的 toast「商品资料更新中」→ 购物车计数仍为 0，用户以为加入了找不到。
- **修复**：
  - detail sheet 的 CTA 同样判 `product.id == null`，置灰 + 文案改「商品资料更新中」
  - 商品卡片右上角加角标区分 fromApi vs 内置（`StatusChip('示例', color: outline)`）

### P1 · 应修（数据一致性 / 资源）

#### F4. `app/lib/pages/data/data_service_page.dart:75` — 失败时 _statSummary / _syncStatus 残留

- **现象**：catch 只重置 `_annualReports` / `_statRecords` / `_loading` / `_error`，summary 和 status 保留上次成功值。
- **触发**：首次加载成功 → hero 显示统计 12 / 同步 30 → 下拉刷新失败 → cache 重建列表 → 头部数字仍是 12/30，但列表是缓存版本 → 数字与可见行不一致。
- **修复**：catch 内追加 `_statSummary = {}; _syncStatus = {};`，hero 显示 0。
- **不推荐**：把这两个 map 也走 OfflineCache —— 注释 line 64 已说明「summary/status 由服务端实时返回」，缓存它们会破坏语义。

#### F5. `app/lib/pages/data/data_service_page.dart:202` — 5 个 TextEditingController 不释放

- **现象**：`_openStatForm` 内分别 new 了 5 个 controller，bottom sheet 关闭后未 dispose。
- **触发**：用户反复开关 sheet（每次 5 个）→ debug 下 Flutter 抛 'used after being disposed'，release 下内存累积。
- **修复**（推荐 A）：
  - **A**：抽成 `_StatFormSheet` StatefulWidget，controller 放 State，`dispose` 释放。
  - **B**：保持函数，`showModalBottomSheet` 后用 `try/finally` 逐个 dispose。

#### F6. `app/lib/core/offline_sync_queue.dart:94, 98` — lastError 丢失原始异常

- **现象**：line 94 `lastError: '同步失败'`（result.failed 分支）；line 98 `catch (_)` 也写 `lastError: '同步失败'`。异常类型与服务端 msg 全部丢弃。
- **触发**：队列里某条记录持续失败（如 422 校验、500 内部错） → 用户在同步日志 sheet 看到两条「同步失败」无法区分原因 → 客服无法定位问题。
- **修复**：
  - line 94：`_submit` 返回结构里携带 detail，写入 `lastError: result.detail ?? '同步失败'`
  - line 98：`catch (e)` → `lastError: '$e'`
- **兼容性**：`SyncQueueItem.next` 已支持 lastError 字符串。
- **口径**：用户层提示仍走中性词（「同步失败，请稍后重试」），diagnostic 信息只在队列项内保留。

### P2 · 可修（维护性）

#### F7. `backend/src/modules/platform/admin.controller.js:151` — group.totalCount 重复累加

- **现象**：`totalCount: resources.reduce(sum + item.count, 0)`，而 summary.recordCount 走 `[...modelCountCache.values()]` 去重；若一个 group 里两个 resource 指向同一 prisma model，group 总数翻倍。
- **触发**：RESOURCE_GROUPS 后续扩张时容易踩坑；当前若无重复 model 暂无明显错误。
- **修复**：
  - groupTotal 也按 model 去重：
    ```js
    totalCount: [...new Set(resources.map(r => r.model))]
      .reduce((sum, m) => sum + (modelCountCache.get(m) || 0), 0)
    ```
  - 配套：SeedDataPage「数据记录」标签改为「业务样例记录」，避免被读成「全表行数」。

#### F8. `backend/src/utils/response.js:68` — errors.offline() 死代码

- **现象**：helper + CODES.OFFLINE 已定义，但 grep 结果显示无任何 throw 站点；ai/sync/dashboard 都还在用 errors.aiBusy 或裸 Error。
- **修复**（推荐接入而非删除）：
  - `backend/src/modules/ai/services/ollama.service.js` 不可达分支：`throw errors.offline('AI 服务暂不可用')` → 控制器 catch 后保留 60002 语义
  - `backend/src/modules/data/sync.controller.js` 回放失败处也改用
- 60002 错误码在 README 与 docs 已固化为「服务暂时不可用」契约，需要真正有调用方。

#### F9. `app/lib/widgets/common.dart:202` — ErrorRetry 图标失去连通性提示

- **现象**：`Icons.cloud_off` → `Icons.error_outline_rounded`，message 改为中性的「服务暂时不可用，请稍后重试」，全局错误屏不再暗示是网络问题。
- **触发**：用户飞行模式 / 后端宕机 → ErrorRetry 全屏 → 用户反复点重试，不会想到检查网络。
- **修复**：
  - ErrorRetry 新增可选 `icon` 参数（默认 `Icons.cloud_off`），调用方按场景覆盖
  - 文案口径不变，提示职责由图标承担
- **替代方案**：保留新图标，message 下方加小字「请检查网络或稍后重试」，给可执行建议。
