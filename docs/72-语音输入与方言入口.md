## 任务

### A. `AppSearchField` 加可选麦克风按钮
- 新增可选参数：`final VoidCallback? onVoice;`（默认 null）。仅当传入时，在搜索框右侧（清除按钮与「搜索」按钮之间或之前）渲染一个麦克风 `IconButton`（`Icons.mic_none`，聚焦色同现有 accent 逻辑）。
- 不传 `onVoice` 时一切照旧（现有所有调用点零影响）。

### B. 语音输入交互（在 search / publish 页各自实现一个本地方法）
- 点麦克风 → 弹一个轻量「正在聆听…」浮层（`showModalBottomSheet`，root navigator，方角 `R.sm`，无大圆角；一个脉冲麦克风图标 + 「正在聆听…」+「松开/点击结束」按钮）。
- 结束后调 `ApiClient` 现有方式 `POST /ai/voice/recognize`（**不带 audio，传 `{}` 或 `{text:''}`**；后端会回示例 transcript）。
- 拿到 `transcript` → 关浮层 → 填入对应输入框：search 页填入搜索框并触发既有搜索；publish 页填入/追加到正文 `TextEditingController`。
- 失败走现有 `toast(context, ...)` 错误提示（用 `serviceErrorMessage`）。

### C. 方言语音入口（#20b）
- 在「正在聆听…」浮层顶部加一行**方言选择 chip**（普通话 / 四川话 / 客家话…，3~4 个，纯前端态）。选中后，请求体带 `dialect` 字段（后端忽略即可，不影响契约），浮层文案显示「正在以〔方言〕聆听…」。这是 demo 入口，体现「支持方言」，不需要真方言模型。

### D. 后端（可选增强，谨慎）
- `voiceRecognize` 现有逻辑保留。若增强：把固定兜底 transcript 改为按 `req.body.scene`/`dialect` 从一个小示例数组里取，**返回字段不变**。不确定就不动后端，只保证现有接口能被前端调通。
