## 五、给 Codex 的硬约束（46 通用）

每份 46x 工作单实施时：

1. **不改后端 schema**。如需后端新接口（46b 的 `DELETE /ai/qa/records`），在工作单内单独列出，Codex 同时改前后端
2. **完成后必跑** `flutter analyze lib`（前端）/ `node --check`（后端改动文件）/ 重启后端确认 OK
3. **不删除既有用户数据**。AI 清空走「软删除 / 软隐藏」而非 hard delete（详见 46b）
4. 每个子任务在工作单末尾追加「实施备注」+ 进度总览改 ✅

## 七、判断标准

完成 46 后，用户再次走查 App，下面 6 个动作必须丝滑：

1. 进入「我的」→ 不见任何手动刷新按钮，下拉刷新生效，数据同步状态自动更新
2. 进入「我的」→ 点「设置」→ 进入真设置页（不再是 toast）
3. 进入「AI」→ 看到 ai_2 会话列表（搜索 + 时间分组 + AI 主动报告徽标）
4. 点会话 → 进入 ai_1 单会话页（带诊断报告卡 + 推荐方案按钮）
5. 单会话「清空全部」→ 服务端记录真删（或软隐藏），返回会话列表不再看到这条
6. 进入「发布」→ 点任意卡片 → 进入详情；点 FAB「+」→ 看到 6+ 种发布类型可选
