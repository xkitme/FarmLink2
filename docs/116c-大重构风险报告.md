# 116c - 田园通大重构风险报告

> 状态：基线风险已识别，等待开工后逐项关闭  
> 适用方案：[116b-大重构三档方案对比.md](116b-大重构三档方案对比.md) B 档  
> 原则：P0 未关闭前，不进入大范围视觉和业务重写。

## 1. 风险分级

| 等级 | 定义 | 处理要求 |
|---|---|---|
| P0 | 可能导致越权、数据损坏、演示阻断或无法回滚 | 对应里程碑开始前必须关闭 |
| P1 | 可能导致核心链路失败、交付不稳定或维护成本失控 | 比赛必达范围内关闭 |
| P2 | 影响体验、长期维护或非核心平台能力 | 可按截止线延期，但必须记录 |

## 2. P0 风险

### R0-01 当前工作区不是正式基线

- **现状**：`main` 上存在约 63 个文件、净删除约一万行的未提交 116 WIP；用户要求先保留。
- **触发**：直接在当前 dirty tree 上继续重构、切换分支或覆盖删除文件。
- **影响**：无法判断新旧改动归属，可能丢失上一代理成果，也无法可靠回滚。
- **缓解**：开工后先建立只读清单和归档分支/工作树；正式重构从 `0b23591f` 创建新分支。
- **关闭标准**：WIP 有可恢复引用；新分支 `git status` 干净；基线 commit 写入报告。

### R0-02 公开注册可提升为 ADMIN

- **现状**：注册接口接受客户端提交的 `role`，现有角色白名单包含 ADMIN。
- **影响**：任意注册者可能取得管理端权限，是明确权限提升漏洞。
- **缓解**：公开注册强制 FARMER；其它角色由 ADMIN 授予；ADMIN 只能通过初始化命令创建。
- **关闭标准**：权限回归测试证明客户端提交任意高权限角色都会被忽略或拒绝。

### R0-03 忘记密码缺少身份所有权证明

- **现状**：用户名和手机号即可重置；第一轮设想的“验证码直接 Toast”同样不构成验证。
- **影响**：知道公开信息即可接管账号。
- **缓解**：比赛离线版由管理台生成单次验证码，5 分钟失效；记录生成者、使用者和审计信息。
- **关闭标准**：验证码不可从用户端获取，不可重放，过期和错误尝试有测试。

### R0-04 默认密钥与演示账号进入 release

- **现状**：JWT、ADMIN JWT 和管理员密码存在代码默认值；管理台预填演示账号。
- **影响**：评委追问安全时无法成立，正式包也可被固定凭据接管。
- **缓解**：dev/demo/release 配置分离；release 缺强密钥时启动失败；比赛包预生成独立密钥。
- **关闭标准**：release 环境使用默认值时后端拒绝启动，secret scan 通过。

### R0-05 离线同步可能跨用户更新

- **现状**：同步控制器按 `localUuid` 查找时未稳定加入 `userId`；业务表缺少匹配唯一约束，日志与业务写入不在同一事务。
- **影响**：UUID 碰撞或已知值可能命中其他用户数据；重试可能产生重复记录。
- **缓解**：全局 UUID 策略、数据库唯一约束、所有查询包含所有者边界、回放与日志同一事务。
- **关闭标准**：跨用户、重复提交、并发重放和失败回滚测试全部通过。

### R0-06 订单可超卖且状态可越级

- **现状**：查库存、建订单、扣库存和物流写入未使用事务；状态只校验枚举值，不校验当前状态到目标状态。
- **影响**：并发超卖、库存错账、买卖双方越权修改状态。
- **缓解**：建立 OrderService、显式状态机、角色动作表和 Prisma transaction。
- **关闭标准**：并发下单不会产生负库存；非法状态跳转返回标准错误；取消回补库存可重复验证。

### R0-07 无可信自动化基线

- **现状**：Flutter 只有一个启动冒烟测试，后端和管理台没有正式测试，仓库没有 CI。
- **影响**：大重构无法区分“原本就坏”与“本次改坏”，里程碑不可安全回滚。
- **缓解**：在结构迁移前补登录、交易、AI、看板等 characterization tests，建立统一验证入口。
- **关闭标准**：基线报告记录所有命令和结果；核心 happy-path/权限/失败态可重复运行。

### R0-08 AI 依赖与比赛硬件目标冲突

- **现状**：历史方案依赖 Ollama 大模型和较重视觉模型；用户明确本机无法稳定承担本地大语言模型，比赛全程断网。
- **影响**：AI 双头牌可能在评委面前超时、冷启动或直接不可用。
- **缓解**：本地大语言模型退出必需依赖；使用轻量植保识别、规则知识库、离线意图路由和确定性降级。
- **关闭标准**：关闭 Ollama 和公网后，AI 植保、知识回答、语音导航仍能完成规定演示脚本。

## 3. P1 风险

### R1-01 语音模型与 APK 体积

- sherpa 模型约 190MB，APK 同时包含 Flutter 和多 ABI 原生库。
- **缓解**：正式包仅 arm64；x86_64 单独构建；模型直接打包；上限调整为 600MB。
- **关闭标准**：arm64 release APK 小于 600MB，断网安装、首次初始化、识别和朗读通过。

### R1-02 Flutter 未加入 PATH

- 实际 Flutter 位于 `C:\dev\flutter`，普通终端的 `flutter` 命令不可用。
- **缓解**：脚本统一探测显式路径并输出版本；工具链版本写入基线。
- **关闭标准**：新终端只需一条项目命令即可完成验证和打包。

### R1-03 磁盘空间和仓库膨胀

- D 盘剩余约 53GB，Git pack 约 825MiB，模型和 Flutter build 会持续占用空间。
- **缓解**：模型、构建产物和数据库备份不进入 Git；设置清理命令；Git 历史瘦身放在比赛后独立执行。
- **关闭标准**：冷构建前自动检查空间；不足阈值时明确阻止打包。

### R1-04 Android release 仍使用 debug 签名

- **影响**：无法作为规范 release 产物，也影响升级安装和技术评分。
- **缓解**：建立独立比赛签名、密钥备份和密码注入流程。
- **关闭标准**：release APK 使用正式签名，校验和、版本号和安装升级测试通过。

### R1-05 API v1/v2 漂移

- **影响**：旧 App、管理台和新 App 可能使用不同字段和错误语义。
- **缓解**：OpenAPI 单一契约、契约测试、一个过渡周期、明确删除日期。
- **关闭标准**：新 App 只调用 v2；管理台契约通过；v1 使用点归零后才删除。

### R1-06 数据库 migration 与旧库兼容

- 当前仓库同时存在 migrations、`db:push` 说明和启动期临时修复。
- **缓解**：统一 migration 基线；升级前备份；启动期一次性修复迁出 HTTP server。
- **关闭标准**：旧 `village.db` 升级、回滚和全新 seed 三条路径均通过。

### R1-07 管理台通用 CRUD 绕过领域规则

- **影响**：管理员可直接把订单、预约和申请改到非法状态。
- **缓解**：参考数据保留通用 CRUD；状态机实体只能调用专用命令 API，并记录审计。
- **关闭标准**：通用资源 API 无法直接写核心状态字段。

### R1-08 上传内容安全

- **现状**：上传缺少文件魔数、解码、重编码和 EXIF 清理，上传目录同源公开。
- **缓解**：只允许 JPEG/PNG/WebP，10MB、9 张上限，服务端解码重编码，随机文件名和配额。
- **关闭标准**：伪扩展名、超大文件、脚本文件和损坏图片均被拒绝。

### R1-09 HTTP、CORS 和 Token 存储

- 比赛局域网允许 HTTP，但当前 CORS 全开放，移动端和管理台凭据存储不安全。
- **缓解**：demo 环境限制可信网段/来源；移动端安全存储；管理台安全 Cookie；正式部署提供 HTTPS。
- **关闭标准**：环境策略自动生效，非允许来源无法访问管理接口。

### R1-10 角色和区域隔离不完整

- **影响**：VILLAGE 可能查看其它区域，ADMIN/FARMER 边界不一致。
- **缓解**：形成角色 × 资源 × 动作矩阵；所有服务层统一执行区域过滤。
- **关闭标准**：横向越权和跨区域测试覆盖六条链路。

### R1-11 模拟 IoT 可能误导

- **影响**：评委追问数据来源时暴露“看似真实、实际随机”的问题。
- **缓解**：产品命名为“设备沙盘”，内部架构和答辩材料明确仿真边界；数据固定可重复，不用随机状态。
- **关闭标准**：演示结果可复现，所有设备动作都有来源和状态记录。

### R1-12 外部知识快照过期

- 市场行情、政策和农业知识在断网环境使用本地快照。
- **缓解**：保存来源 URL、数据日期、导入日期和版本；比赛前执行一次更新检查。
- **关闭标准**：界面和答辩均能说明来源及更新时间，过期数据有明确状态。

## 4. P2 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 文档状态漂移 | 新成员读到过时 45/115/旧 116 | 进度总览、交接簿和工作单同步更新，历史计划标记被取代 |
| 暗色模式后加 | 重复修改大量颜色和图标 | 先建立语义化 token，再迁页面 |
| 动效“稳定但多” | 低端机掉帧或弹窗卡顿 | 动效预算、RepaintBoundary、真机帧率走查 |
| 无障碍范围过大 | 赛前难以一次完成 | 核心链路优先 WCAG 2.1 AA，辅助页后补 |
| Linux 支持 | 与 Windows 脚本分叉 | 先统一 Node/Flutter 命令，再补轻量 Linux 脚本 |
| 技术名改为 FarmLink | 路径、包名、签名和脚本连锁变化 | 用户可见品牌先统一，技术标识最后独立迁移 |
| 一人开发范围过大 | 关键链路来不及收口 | 使用比赛必达/应达/可延期截止线 |

## 5. 里程碑风险闸门

| 闸门 | 必须满足 |
|---|---|
| G0 基线闸门 | WIP 可恢复、新分支干净、工具链与现状测试已记录 |
| G1 安全闸门 | 注册提权、密码重置、默认密钥、上传阻断项关闭 |
| G2 数据闸门 | 订单事务、同步隔离、migration/备份/恢复通过 |
| G3 架构闸门 | v2 契约、能力注册表、样板领域可运行 |
| G4 双头牌闸门 | 交易和 AI 植保在完全断网下真机通过 |
| G5 比赛闸门 | 一键启动、APK、种子数据、三分钟脚本、回滚包全部通过 |

任何闸门未通过，不得以“页面看起来完成”为由进入下一阶段。
