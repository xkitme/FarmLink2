## F7 · group.totalCount 按 model 去重

**文件**：`backend/src/modules/platform/admin.controller.js`
**配套**：`backend/admin/src/pages/SeedDataPage.jsx`

原 `totalCount = resources.reduce((sum, item) => sum + (item.count || 0), 0)`
逐 resource 累加，若一个 group 内两个 resource 指向同一个 prisma model，
则该 model 的行数被加两次，与顶层 `summary.recordCount` 的 modelCountCache 去重
方式不一致。

**改动**：

```js
const seenModels = new Set()
let totalCount = 0
for (const item of resources) {
  if (!item.model || item.model === '-' || seenModels.has(item.model)) continue
  seenModels.add(item.model)
  totalCount += item.count || 0
}
```

同时把 SeedDataPage 中 `Statistic title="数据记录"` 改为 `"业务样例记录"`，
明确这是「资源配置覆盖到的行数」而非「全表行数」。

## F8 · errors.offline 改为契约预留 + 注释

**文件**：`backend/src/utils/response.js`

review 时发现 `errors.offline()` 无调用方。重新评估发现：

- AI 链路有 fallbackAnswer 兜底，不应抛 60002（产品口径要求"服务永远兜底"）
- sync 链路已经把失败归类到 `results[i].detail`，不抛异常
- 没有合适的当前接入点

**决策**：保留 helper 与 60002 错误码契约，作为对外协议预留。补完整 JSDoc
说明适用场景（外部支付、短信下行等"无兜底依赖"场景），并加入口注释
避免被未来的死代码扫描误删。

```js
/**
 * 服务暂时不可用 (60002)
 * 当前 AI / sync 链路均有兜底，不会向客户端抛 60002。
 * 本 helper 作为对外错误码契约预留，未来若新增「无兜底依赖」
 * 的能力（外部支付、短信下行）应使用此助手。
 */
offline: (msg = '服务暂时不可用，请稍后重试') => new BusinessError(CODES.OFFLINE, msg),
```

## F9 · ErrorRetry 加可选 icon 参数

**文件**：`app/lib/widgets/common.dart`

`Icons.error_outline_rounded` 在中性 message「服务暂时不可用」面前，丢失了
「可能是网络问题，可以试试重试」的暗示。

**改动**：

```dart
class ErrorRetry extends StatelessWidget {
  final String message;
  final VoidCallback onRetry;
  final IconData icon;
  const ErrorRetry({
    super.key,
    required this.message,
    required this.onRetry,
    this.icon = Icons.cloud_off,  // 默认走「连通性」暗示
  });
  ...
}
```

调用方默认行为不变，业务侧错误（非连通性）可显式传 `icon: Icons.error_outline_rounded`
覆盖。文案口径不动，提示职责由图标承担。
