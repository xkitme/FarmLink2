# 116m - FarmLink 项目总收尾工单

## 1. 工单定位

本工单用于 FarmLink 项目最终收尾。执行者身份不是单一功能开发 Agent，而是 **Release QA + 本地运行验收 + 最终文档收口 Agent**。

目标不是继续扩大功能，而是把当前已经 CI 全绿的主线推进到以下状态：

- 本地后端、Flutter Web、Admin 可同时运行。
- Flutter 登录后能稳定连接后端。
- 核心路径完成冒烟验收。
- 文档口径与当前 main 一致。
- 数据库、Prisma、生成产物风险可解释。
- 若需要修复，走 PR + CI；若无需修复，输出无需 PR 的收尾报告。

## 5. 开工核验

先执行：

```powershell
git fetch origin --prune
git status --short --branch --untracked-files=all
git rev-parse HEAD
git rev-parse origin/main
gh pr list --state open --json number,title,headRefName,baseRefName,mergeable,url
```

需要确认：

- 本地是否在 `main`。
- 本地 `main` 是否等于 `origin/main`。
- `origin/main` 是否为 `7402e5ae7a5ff68e99b4f9558d752e61dd38838e` 或更新。
- 是否存在 open PR。
- 工作树是否干净。

如果本地 main 落后，允许 fast-forward：

```powershell
git checkout main
git merge --ff-only origin/main
```

禁止使用 `git reset --hard`。

## 10. 后端接口冒烟

必须覆盖：

```text
GET  /health 或 /api/v1/ping
GET  /api/v1/market/price
POST /api/v1/auth/login
GET  /api/v1/auth/me
GET  /api/v1/ai/assistant/config
GET  /api/v1/market/order/list?role=buyer&pageNum=1&pageSize=50
GET  /api/v1/data/dashboard
```

重点验收 `/api/v1/ai/assistant/config`：

- 未登录返回 401 是正确行为。
- 登录后带 token 或 cookie 返回 200。
- 如果登录后仍 401，必须定位：
  - token 未保存。
  - Flutter baseUrl 错。
  - API prefix 错。
  - CORS / cookie / credentials 问题。
  - 后端 auth middleware 问题。

## 21. 停止条件

遇到以下情况立即停止并报告：

- `git fetch` 连续 2 次网络失败。
- `origin/main` 与本地基线分叉。
- 正式 DB 指纹在未授权情况下变化。
- Prisma schema/migrations 出现在 diff。
- 生成产物 drift 无法解释。
- Flutter SDK 找不到且任务必须本地 build。
- scope-check 需要宽泛放行才能通过。
- CI 非绿。
- 端口被未知进程占用且无法确认来源。
- 登录后 `/api/v1/ai/assistant/config` 仍 401。

## 22. 完成标准

只有同时满足以下条件，才可以声明“项目收尾完成”：

- 最新 main 本地已同步。
- open PR 为 0，或剩余 PR 已明确说明为何保留。
- 本地 Backend + Flutter Web + Admin 可运行。
- Flutter 登录后能连上后端。
- `/api/v1/ai/assistant/config` 未登录 401、登录后 200。
- 首页和全部服务符合 6 主路径新口径。
- Backend/Admin/scripts/drift 全部本地通过。
- Flutter 本地通过，或明确说明本机缺 SDK 并以远端 CI Flutter SUCCESS 作为 CI 层事实。
- 截图/日志证据已归档。
- `docs/进度总览.md` 不再滞后。
- DB/Prisma/生成产物风险为 0，或已明确报告阻断原因。
