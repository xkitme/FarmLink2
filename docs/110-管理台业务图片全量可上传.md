# 110 · 管理台业务图片全量可上传

## 目标

让后端「所有需要图片的地方」都能在管理台直接上传/更换图片，覆盖流通销售（商品）、
生产农业（农事记录）等全部业务实体，而不再只能手动粘贴图片 JSON。

## 背景

排查现状发现：

- 通用上传端点 `POST /api/v1/upload/image` 早已存在，返回 `{ url: '/uploads/<file>' }`。
- 管理台 `ResourcePage` 已有**单图**上传控件 `ImageUploadField`（`type:'image'`），
  但只用在用户的 `avatarUrl 头像`、`bannerUrl 封面`。
- 业务实体的多图字段 `images` 在 `resource.config.js` 里被声明为 `type:'json'`，
  在管理台里只是一个**裸 JSON 文本框**——管理员只能手敲 `["url1","url2"]`，没有真正的上传体验。
- 受影响实体共 **10 个**：商品 product、农事记录 farmRecord、农机 machinery、
  灾情上报 disasterReport、溯源记录 traceRecord、旅游 tourismSpot、二手 secondhandItem、
  荣誉 honorRecord、环境举报 envReport、反馈 feedback。
- 站点配图（Logo / 登录大图 / 横幅）另有独立「站点配图」页，不在本次范围。

即「后端能存图 URL，但管理台没有可用的上传入口」。本次补齐这个缺口。

## 改动

沿用既有架构，新增一个**多图**字段类型 `images`，DB 存储格式保持不变（JSON 数组字符串）。

1. **`backend/admin/src/pages/ResourcePage.jsx`**
   - 新增 `parseImages(value)`：把 DB 的 JSON 数组字符串安全解析为 URL 数组，
     兼容空值 / 已是数组 / 遗留裸 URL。
   - 新增多图控件 `ImagesUploadField`：多选上传到 `/upload/image`、缩略图网格（逐张删除）、
     「清空」、手动填 URL 追加；回写为 JSON 字符串。
     批量并发上传用 `useRef` 串行累加，避免闭包旧值相互覆盖。
   - `formatValue` 增加 `type:'images'` 列渲染：最多 3 张缩略图 + `+N` 角标。
   - `FieldInput` 增加 `type:'images'` → `ImagesUploadField` 路由。
2. **`backend/src/modules/platform/resource.config.js`**
   - 把上述 10 个实体的 `field('images', '图片JSON', 'json')` 改为 `field('images', '图片', 'images')`。
3. **`backend/src/modules/platform/resource.controller.js`**
   - `parseValue` 把 `images` 类型并入 `json` 分支：字符串原样存（否则会落到默认
     `String(value)` 把数组拼成 `url1,url2` 而损坏数据）。

## 契约

- `images` 字段在管理接口 `GET /admin/resource/:resource/config` 中类型为 `images`。
- 写接口 `POST/PUT /admin/resource/:resource[/:id]` 接收 `images` 为 **JSON 数组字符串**，
  原样存入 DB（与历史 `json` 格式完全一致）。
- DB 实际存储示例：`["/uploads/1782133581570_ddgkje.jpg"]`。
- 移动端 / 种子数据 / 存量数据无需改动，照旧解析。

## 验收

- 后端 `node --check` 两文件通过；管理台 `npm run build` 通过。
- 接口往返：`PUT /admin/resource/product/64` 写两张图 → 200 → DB 读回为
  `["/uploads/a.jpg","/uploads/b.jpg"]`、可正确 `JSON.parse`（验后已还原）。
- 浏览器实测（`:8000/admin/` admin 登录 → 流通销售 → 商品 → 编辑）：
  - 「图片」字段渲染为「上传图片」按钮 + 手动填 URL；
  - 上传一张图 → 缩略图带删除角标出现、按钮变「继续添加 / 清空」；
  - 点「确定」保存 → DB 落库为新上传的 `/uploads/...` URL。
  - （验证用的测试商品图片与上传文件均已还原/清理。）

## 不在范围

- 站点配图（Logo / 登录大图 / 横幅）：另有独立「站点配图」页。
- 移动端用户自助上传链路：本次只补管理台。
- 单图字段（头像 / 封面）：维持原 `image` 控件。
- 图片裁剪 / 压缩 / 排序拖拽：未做（仅增删 + 追加）。

## 实施备注

- 10 个实体共用同一套 `ResourcePage` + 字段类型，故只需改配置 + 一个控件即全量生效；
  浏览器用商品做代表验证。
- 上传 URL 为相对 `/uploads/...`：vite dev 已代理 `/uploads`，生产由后端 `express.static` 托管，
  两端缩略图都能显示。存量 `assets/images/...` 资产路径在管理台不解析（仅预览限制，不影响数据）。
- 改了 `resource.config.js` 后端需重载（nodemon 自动）；改了管理台需重新 `npm run build`
  才会被后端 `/admin` 托管。
