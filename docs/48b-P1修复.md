## G4 · qaClearAll 与 SSE in-flight race

### 现状

`qaClearAll` 立即 `deleteMany`，但 `askScene` 的 SSE 完成后才 `prisma.aiQaRecord.create` —— 清空时正在生成的 record 会在 deleteMany 之后写入，逃过清空。

### 改动

`backend/src/modules/ai/ai.controller.js:qaClearAll` 改：

```js
export async function qaClearAll(req, res) {
  const userId = req.user.id
  // 用事务 + 时间戳门槛：deleteMany 后记录清除时间；同会话中后续 create 检查
  // 简化方案：删除前 + 删除后两次扫描
  const cutoff = new Date()
  const before = await prisma.aiQaRecord.deleteMany({ where: { userId, createdAt: { lte: cutoff } } })
  // 短暂等待潜在的 in-flight SSE 落库
  await new Promise((r) => setTimeout(r, 1500))
  const after = await prisma.aiQaRecord.deleteMany({ where: { userId, createdAt: { lte: new Date() } } })
  ok(res, { deleted: before.count + after.count }, '已清空 AI 对话历史')
}
```

> 1500ms 是一个折中值：足以让大部分流式回答（已经在 onDelta 流末端、即将 create）落库被第二次扫到，但不会让用户感觉明显卡顿。

**更稳的备选**：在 `askScene` 内部 create 之前再查一遍「该 userId 是否有最近的 clearAll 操作」（需要新表记录 clearLog）—— 工作量大，本工作单不采用。

### 验收

1. 浏览器开两个窗口同一用户。窗口 A 发起一个长问题（让 SSE 流式回答约 5-10 秒）
2. 窗口 B 在 A 的 SSE 流式过程中点「清空全部」
3. SSE 完成后等 2 秒，刷新窗口 B 列表 → 不再出现刚才那条流式回答

## G5 · ADMIN clearAll 行为对齐

### 现状

`qaRecords` 给 ADMIN 返回全平台数据（where={}），但 `qaClearAll` 始终按 userId 删除 —— 列表看到 80 条，清空后只删自己的 10 条。

### 改动

#### 5.1 后端 `qaClearAll` —— ADMIN 支持范围清空

```js
export async function qaClearAll(req, res) {
  const isAdmin = req.user.role === 'ADMIN'
  // ADMIN 可通过 body.scope = 'all' / 'mine' 控制；默认 'mine'
  const scope = isAdmin && req.body.scope === 'all' ? 'all' : 'mine'
  const where = scope === 'all' ? {} : { userId: req.user.id }
  // race 处理同 G4
  const r1 = await prisma.aiQaRecord.deleteMany({ where })
  await new Promise((r) => setTimeout(r, 1500))
  const r2 = await prisma.aiQaRecord.deleteMany({ where })
  ok(res, { deleted: r1.count + r2.count, scope }, '已清空')
}
```

#### 5.2 前端 `ai_threads_page.dart` —— ADMIN 二次确认让用户选范围

```dart
Future<void> _clearAll() async {
  final auth = context.read<AuthState>();
  final isAdmin = auth.user?.role == 'ADMIN';
  String scope = 'mine';
  if (isAdmin) {

      context: context,
      builder: (ctx) => AlertDialog(
        title: const Text('清空范围'),
        content: const Text('您是管理员，请选择清空范围：'),
        actions: [
          TextButton(onPressed: () => Navigator.pop(ctx), child: const Text('取消')),
          TextButton(
            onPressed: () => Navigator.pop(ctx, 'mine'),

          ),
          TextButton(
            onPressed: () => Navigator.pop(ctx, 'all'),
            child: const Text('全平台', style: TextStyle(color: AppColors.error)),
          ),
        ],
      ),
    );
    if (choice == null) return;
    scope = choice;
  } else {
    final ok = await showDialog<bool>(...原确认 dialog...);
    if (ok != true) return;
  }
  await ApiClient.delete('/ai/qa/records', body: {'scope': scope});
  // ApiClient.delete 若不支持 body，改用 POST /ai/qa/records/clear
  ...
}
```

> `ApiClient.delete` 通常不带 body。建议：把 `DELETE /ai/qa/records` 改为 `POST /ai/qa/records/clear`，body 含 `{scope}`，更符合 HTTP 语义且 ApiClient 支持。
> 后端 routes 同步：`router.post('/ai/qa/records/clear', wrap(ai.qaClearAll))`

### 验收

1. ADMIN 登入 → AI threads 看到全平台数据
2. 点「清空全部」→ 弹「仅我自己 / 全平台」对话框
3. 选「仅我自己」→ 列表只剩其他用户的 records
4. 再点「清空全部」→ 选「全平台」→ 列表清空
5. 普通用户登入 → 同按钮只弹「是否清空」二次确认，无范围选

## G6 · composer controller 释放

### 现状

`publish_page.dart:_openComposer` 内 `titleC` / `contentC` / `phoneC` 三个 `TextEditingController` 是函数内局部变量，sheet 关闭后从未 dispose。

### 改动

把 composer 抽成 `_PublishComposerSheet` StatefulWidget，controller 放 state，dispose 中释放：

```dart
class _PublishComposerSheet extends StatefulWidget {
  const _PublishComposerSheet();
  @override
  State<_PublishComposerSheet> createState() => _PublishComposerSheetState();
}

class _PublishComposerSheetState extends State<_PublishComposerSheet> {
  final _titleCtrl = TextEditingController();
  final _contentCtrl = TextEditingController();
  final _phoneCtrl = TextEditingController();
  String _type = '互助求助';

  @override
  void dispose() {
    _titleCtrl.dispose();
    _contentCtrl.dispose();
    _phoneCtrl.dispose();
    super.dispose();
  }

  void _submit() { Navigator.pop(context, _ComposerResult(...)); }

  @override
  Widget build(...) { ... 原内容 ... }
}

class _ComposerResult {
  final String type;
  final String title;
  final String content;
  final String phone;
  const _ComposerResult({...});
}
```

外层 `_openComposer`：

```dart
final result = await showModalBottomSheet<_ComposerResult>(
  context: context,
  isScrollControlled: true,
  ...
  builder: (_) => const _PublishComposerSheet(),
);
if (result == null || !mounted) return;
await _submit(result.type, {
  'type': result.type,
  'title': result.title,
  'content': result.content,
  'contactPhone': result.phone,
});
```

### 验收

1. `flutter analyze lib/pages/publish` → No issues
2. debug build 反复打开关闭 composer 10 次 → 控制台无 'used after disposed' 警告
3. release 测试：内存使用稳定（DevTools memory tab 观察）

## G9 · dashboard aiCallCount 单调化

### 现状

`dashboard.aiCallCount = aiQaRecord.count() + aiDetectRecord.count()`，用户删 record 后 dashboard 数字回落。

### 改动

#### 9.1 引入累计计数表

`schema.prisma` 新增（或复用 platform_stat 模型）：

```prisma
model PlatformCounter {
  key       String   @id           // 'ai_chat_total' / 'ai_detect_total' / ...
  value     Int      @default(0)
  updatedAt DateTime @updatedAt
  @@map("t_platform_counter")
}
```

#### 9.2 ai.controller.js 每次成功 create record 后 +1

```js
import { incCounter } from '../../utils/counter.js'

// askScene 成功 create 后：
await incCounter('ai_chat_total')

// imageAnalyze 成功 create 后：
await incCounter('ai_detect_total')
```

`backend/src/utils/counter.js`：

```js
import { prisma } from '../db.js'

export async function incCounter(key, by = 1) {
  await prisma.platformCounter.upsert({
    where: { key },
    create: { key, value: by },
    update: { value: { increment: by } },
  })
}

export async function readCounter(key) {
  const row = await prisma.platformCounter.findUnique({ where: { key } })
  return row?.value || 0
}
```

#### 9.3 dashboard.controller.js 改用累计值

```js
import { readCounter } from '../../utils/counter.js'

// 原代码
// const aiQaCount = await prisma.aiQaRecord.count()
// const aiDetectCount = await prisma.aiDetectRecord.count()

// 改为
const [aiQaCount, aiDetectCount] = await Promise.all([
  readCounter('ai_chat_total'),
  readCounter('ai_detect_total'),
])
```

#### 9.4 一次性回填

```js
// backend/scripts/backfill-counter.js
import { prisma } from '../src/db.js'
const chat = await prisma.aiQaRecord.count()
const detect = await prisma.aiDetectRecord.count()
await prisma.platformCounter.upsert({
  where: { key: 'ai_chat_total' }, create: { key: 'ai_chat_total', value: chat },
  update: { value: chat },
})
await prisma.platformCounter.upsert({
  where: { key: 'ai_detect_total' }, create: { key: 'ai_detect_total', value: detect },
  update: { value: detect },
})
console.log(`回填 ai_chat_total=${chat} ai_detect_total=${detect}`)
process.exit(0)
```

跑：`node scripts/backfill-counter.js`

### 验收

1. dashboard 查看 aiCallCount → 显示某值 N
2. AI threads 点「清空全部」（自己 10 条）→ 等几秒
3. dashboard 刷新 → aiCallCount 仍为 N（不回落）
4. 发起新对话 → dashboard aiCallCount = N + 1
