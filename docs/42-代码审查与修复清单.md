### G1 · 队列空 detail 覆盖 fallback，诊断信息丢失（P0）

**文件**：`app/lib/core/offline_sync_queue.dart:99`

`flush()` failure/conflict 分支：

```dart
lastError: result.detail ?? '同步失败',
```

`??` 只在 null 时退回。服务端返回 `{status:'FAILED', detail:''}` 是非常常见的默认空串，会让 `lastError` 写成空字符串。`_localTile` 内 `item.lastError!.isNotEmpty` 失败 → 失败 chip 下不显示任何原因 → F6 修复直接失效。

**修复**：

```dart
final detail = result.detail;
lastError: (detail != null && detail.isNotEmpty) ? detail : '同步失败',
```

或者在 `_submit` 内 trim 后归 null。CONFLICT 分支同样改。

### G2 · _SyncLogsSheet 不响应 parent state 变化（P0）

**文件**：`app/lib/pages/data/data_service_page.dart:288`

`_SyncLogsSheet` 接收 `localQueue` / `flushing` 作为构造参数。bottom sheet 在独立的 element 树里，`DataServicePage` 的 setState 不会跨树触发 sheet rebuild。

用户在 sheet 内点「立即同步」：
- 内部 spinner 永不显示
- 按钮维持可点状态（重复触发 _flushQueue）
- 队列列表不刷新，直到关闭 sheet 后外层 `_load()` 才让数据看起来正确

分段 40 的核心交互（sheet 内查看 + 立即同步）失效。

**修复**：

把 `localQueue` 与 `flushing` 改成共享状态：

```dart
// 推荐：用 ValueNotifier
final _localQueueNotifier = ValueNotifier<List<SyncQueueItem>>([]);
final _flushingNotifier = ValueNotifier<bool>(false);
```

sheet 内用 `ValueListenableBuilder` 监听。flush 进度由 `_flushingNotifier.value = true/false` 驱动；_load 完成后 `_localQueueNotifier.value = newList`。

或者：sheet 自己 StatefulWidget，flush 由 sheet 内部直接 `OfflineSyncQueue.flush()`，结束后通过 callback 通知父页面刷新汇总。

### G6 · data_service _load catch 内 await 异常可让 _loading 永卡（P1）

**文件**：`app/lib/pages/data/data_service_page.dart:91`

catch 分支：

```dart
} catch (e) {
  if (!mounted) return;
  final annual = await OfflineCache.readList('data_annual_report');   // 1
  if (!mounted) return;
  final stat = await OfflineCache.readList('data_stat_report');       // 2
  if (!mounted) return;
  final queue = await OfflineSyncQueue.all();                          // 3
  ...
}
```

任意 1/2/3 抛 `MissingPluginException` 或 `PlatformException`（SharedPreferences 平台通道异常）会冒到 `_load` 之外，最后那次 setState `_loading=false` 永不执行 → 页面卡 Loading + AppBar refresh 按钮被 `_loading=true` 禁用 → 用户无法重试只能杀进程。

**修复**：

catch 内再裹一层 try/catch，或用 finally 保证 setState：

```dart
} catch (e) {
  if (!mounted) return;
  List<Map<String, dynamic>> annual = [];
  List<Map<String, dynamic>> stat = [];
  List<SyncQueueItem> queue = [];
  try {
    annual = await OfflineCache.readList('data_annual_report');
    if (!mounted) return;
    stat = await OfflineCache.readList('data_stat_report');
    if (!mounted) return;
    queue = await OfflineSyncQueue.all();
  } catch (_) {
    // 缓存读取失败也不阻塞 UI
  }
  if (!mounted) return;
  setState(() {
    _annualReports = annual;
    _statRecords = stat;
    _statSummary = {};
    _syncStatus = {};
    _localQueue = queue;
    _loading = false;
    _error = serviceUnavailableMessage;
  });
}
```

### G7 · login 后 ShellPage 不重新 refresh，未读徽标停留 0（P1）

**文件**：`app/lib/pages/home/shell_page.dart:34` + `app/lib/core/auth_state.dart`

**修复**：

```dart

Future<void> login(String username, String password) async {
  ...
  ApiClient.setToken(data['accessToken']);
  ...
  unawaited(NotificationState.refresh());
  notifyListeners();
}
```

### G9 · ShellPage refresh 双触发 + 无版本化竞态（P2）

**文件**：`app/lib/pages/home/shell_page.dart:38`

- initState postFrame 调度一次 refresh
- 首次 didChangeDependencies 因 `_lastLocation == null` 必通过等式检查，再调度一次
- 两次并发 GET `/notification/unread`，若启用 rate-limit 第二次 429 被静默吞
- 用户连点底栏切换时，并发响应若乱序，旧响应可能覆盖新值（messages_page 自己也 setUnread）

**修复**：

```dart
// notification_state.dart
class NotificationState {
  static int _refreshSeq = 0;
  static Future<void> refresh() async {
    final seq = ++_refreshSeq;
    try {
      final data = await ApiClient.get('/notification/unread');
      if (seq != _refreshSeq) return;  // 旧响应被丢弃
      setUnread(_int(data['unread']));
    } catch (_) {}
  }
}
```

并把 ShellPage 的 initState 调用去掉（didChangeDependencies 首次必走，足够）：

```dart
@override
void initState() {
  super.initState();
  // refresh 由 didChangeDependencies 触发，不在此重复
}
```

### G10 · notification.controller groupBy 包含 null type，typeCounts 出现 'null' 键（P2）

**文件**：`backend/src/modules/platform/notification.controller.js:20`

`typeGroups = prisma.notification.groupBy({ by: ['type'], _count: { _all: true }, where: baseWhere })` 不过滤 `type IS NULL`。`Object.fromEntries([[null, N]])` 转成 `{'null': N}` 后塞进 typeCounts，污染响应。

同时 `unread` 字段使用 baseWhere（忽略 type 查询参数），若客户端发 `?type=ALERT` 期望「未读 ALERT」会拿到全局 unread —— 契约不直观。

**修复**：

```js
const typeGroups = await prisma.notification.groupBy({
  by: ['type'],
  _count: { _all: true },
  where: { ...baseWhere, type: { not: null } },
})
// 同时 unread 也按 type 过滤（如果有 typeQuery）
const unreadWhere = typeQuery ? { ...baseWhere, type: typeQuery, isRead: false } : { ...baseWhere, isRead: false }
```

或在 fromEntries 前 filter 掉 null/空 key（次选）。
