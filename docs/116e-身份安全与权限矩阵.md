# 116e - 身份、安全与权限矩阵

> 状态：进行中  
> 上位计划：[116-大重构总计划.md](116-大重构总计划.md)  
> 决策来源：[116a-大重构决策记录.md](116a-大重构决策记录.md)

## 目标

在任何业务领域迁移前关闭身份与配置 P0，建立后端强制执行的角色、区域和会话边界。比赛离线环境允许局域网 HTTP，但身份校验、密钥、重置码和上传边界不能因“离线”而降级。

## 风险基线

1. `POST /api/v1/auth/register` 接受客户端 `role`，可直接注册为 `ADMIN`。
2. 忘记密码仅校验账号与手机号，知道公开资料即可改密。
3. access token 与 refresh token 共用密钥、没有 token 类型，refresh token 可被当作 access token 使用。
4. release 环境存在使用默认 JWT 密钥启动的可能。
5. 当前 JWT 无持久会话，无法 rotation、单设备撤销和强制下线。
6. 管理台与移动端尚未采用目标凭据存储方案；上传边界也未完全收口。

## 权限矩阵

| 能力 | FARMER | BIGFARMER | VILLAGE | EXPERT | MERCHANT | ADMIN |
|---|---:|---:|---:|---:|---:|---:|
| 公开注册所得角色 | ✅ | - | - | - | - | - |
| 修改本人资料/密码 | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| 购买农产品 | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| 发布普通农产品 | - | ✅ | - | - | ✅ | ✅ |
| 村级经营数据 | - | - | 本区域 | - | - | 全域 |
| 授予非 ADMIN 角色 | - | - | - | - | - | ✅ |
| 创建/授予 ADMIN | - | - | - | - | - | 仅受控初始化命令 |
| 生成密码重置码 | - | - | - | - | - | ✅ |
| 撤销其它用户会话 | - | - | - | - | - | ✅ |

权限规则以服务端为准。Flutter 的入口隐藏和管理台按钮禁用只是体验层，不能代替后端校验。

## 环境契约

新增 `APP_ENV`：

- `dev`：本机开发，可使用明确标记的开发密钥和种子账号。
- `demo`：比赛离线包，允许固定演示账号，但必须使用独立强密钥。
- `release`：正式发布；缺少强密钥、密钥相同或命中已知默认值时拒绝启动。

未提供 `APP_ENV` 时，`NODE_ENV=production` 按 `release` 处理，其余按 `dev` 处理。access token 与 refresh token 必须使用不同密钥；`demo/release` 密钥至少 32 个字符。

## API 契约

### 公开注册

`POST /api/v1/auth/register`

- 接受：`username`、`password`、`nickname`/`displayName`、`phone`。
- 忽略并拒绝信任：`role`、`regionCode`、`villageName`、`status` 等权限字段。
- 服务端固定写入 `role=FARMER`、`regionCode=null`、`villageName=null`。
- 登录响应外形暂不改变，避免阻断 Flutter 现有调用。

### Token

- access token 载荷包含 `tokenType=access`，只能访问业务接口。
- refresh token 载荷包含 `tokenType=refresh`，只能访问刷新接口。
- 两种 token 使用不同密钥；类型或密钥不匹配统一返回 401。
- Phase B 引入持久会话后，refresh 成功必须 rotation，旧 refresh token 立即失效。

### 离线密码重置

1. ADMIN 在管理台为指定账号生成 6 位一次性码。
2. 只向当前 ADMIN 返回一次明文；数据库只保存哈希。
3. 重置码 5 分钟失效、最多尝试 5 次、成功后立即作废。
4. 用户端提交 `username`、`resetCode`、`newPassword`；不再以手机号作为身份证明。
5. 改密成功后撤销该用户全部会话。

## 分期实施

### Phase A - 阻断即时提权

- 公开注册固定 FARMER，并兼容 Flutter 的 `displayName` 字段。
- access/refresh token 分离密钥和类型。
- `dev/demo/release` 配置解析与 release fail-fast。
- 增加 Node 内置测试与统一验证入口。

### Phase B - 可撤销会话与一次性重置码

- 新增 `AuthSession`、`PasswordResetCode` 模型与正式 migration。
- refresh rotation、logout 撤销、设备列表、单设备/全设备下线。
- 管理台重置码生成接口与用户重置接口。
- 登录失败审计和重置码暴力尝试限制。

### Phase C - 客户端与外围安全

- Flutter 凭据迁到系统安全存储。
- 管理台改为安全 Cookie，会话过期体验对齐。
- CORS allowlist、代理来源信任、审计日志脱敏。
- 上传执行 MIME/解码校验、重编码、EXIF 清理和数量配额。
- 比赛 HTTP 与正式 HTTPS 构建策略分离。

## 验收

- 携带 `role=ADMIN`、`VILLAGE` 或区域字段注册后，数据库角色仍为 FARMER 且无区域。
- refresh token 访问普通受保护接口返回 401；access token 调刷新接口返回 401。
- `APP_ENV=release` 配默认、过短或相同密钥时，服务拒绝启动。
- 重置码过期、重放、错误超过上限均失败；成功改密后旧会话全部失效。
- FARMER/其它普通角色无法调用角色授予和重置码生成接口。
- `npm test --prefix backend`、统一验证脚本和受影响的 Flutter 测试通过。

## 不在范围内

- 不在本工单迁移交易、AI、农机等领域结构。
- 不建立公网短信服务；比赛离线版由管理台完成身份协助。
- 不把 HTTP 本身伪装成安全传输；正式 release 必须执行 HTTPS 方案。
- 不在用户界面显示“比赛”“Demo”“开发”“占位”等字样。

## 回滚

- 数据库新增表通过对应 migration 回滚或保留为空表，不改写现有业务数据。
- 登录响应保持兼容；如客户端安全存储迁移失败，可临时读取旧值并立即迁移，不能恢复公开提权或手机号直接重置。
- 已知安全漏洞修复不得回退，仅允许修复兼容层。
