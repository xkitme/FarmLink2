# 分段 99 — AI 语音助手 P1 业务闭环（订单页 + 收货地址 + 下单/支付贯通）

> doc 92 规划的语音助手分 P0/P1/P2。P0（助手骨架/覆盖层/白名单 command schema/DeepSeek 编排）早已完成，但进度总览一直挂着「🔄 P0 代码完成，P1 待办」。用户问「AI 语音助手呢？不是没写完吗？」——本段把 **P1 业务闭环**补齐：我的订单页、`shippingAddress` 收货地址、订单确认读资料地址、下单→mock 支付贯通、seed 演示商品。

## 一、开工核实（避免凭 doc 假设）

逐一核实 P0 之后的真实状态：
- 后端订单**模型 + API 已完整**：`Order` 表 + `POST /market/order`(下单含扣库存) / `GET /market/order/list`(买卖家视角) / `GET /market/order/:id` / `PUT /market/order/:id/status`(状态机 PENDING→PAID→SHIPPED→DONE/CANCELLED，发货生成物流、取消回补库存) / 物流追踪。`receiverInfo` 以 JSON 字符串存储（**地址无需改订单表结构**）。
- 前端 `_executeCommand` 的 `create_order`/`mock_pay` 已接真实端点。
- **真实缺口**：① `/market/orders` 仍是占位（`orders` routeKey 落到 `/market`，状态文案「订单页将在下一阶段接入」）② `User` 无 `shippingAddress`、资料页无收货地址 ③ 订单确认未读资料地址 ④ 无手链/玩偶演示商品 ⑤ 后端 `create_order` 校验**硬要求 receiverInfo**，与「App 用资料地址兜底」冲突。

## 二、改动

### 后端
- `prisma/schema.prisma`：`User` 加 `shippingAddress String?`；手写 migration `20260618120000_add_user_shipping_address`（`ALTER TABLE t_user ADD COLUMN shippingAddress TEXT`），`migrate deploy` 应用 + `prisma generate`（`sanitizeUser` 只剥密码，故自动带出该字段，无需改）。
- `user.controller.js#updateProfile`：收 `shippingAddress`（空串→null）。
- `seeds/index.js`：merchant 名下加「环保编织手链」「乡村文创玩偶」两件文创商品（演示「推荐手链/玩偶」用；图先留占位）。
- `assistant.service.js`：`create_order` 校验**去掉 receiverInfo 必填**（改为可选透传）——收货信息由 App 用登录用户资料里的收货地址兜底。
- `assistant-config.service.js`：命令 schema `create_order` 去掉 receiverInfo 形参；规则 3 改为「先 show_order_confirm 确认、用户确认后再 create_order；收货信息 App 自动用资料地址填充，模型无需索要地址」。

### 前端
- `models/user.dart`：`AppUser` 加 `shippingAddress`（构造/fromJson/toJson）。
- `pages/profile/settings/account_edit_page.dart`：加「收货地址」输入项（读 `user.shippingAddress`，保存随 PUT `/user/profile` 提交）。
- 新建 `pages/market/orders_page.dart`「我的订单」：`GET /market/order/list?role=buyer`，订单卡（订单号/中文状态徽章/商品标题/数量/金额/收货信息），下拉刷新 + 空态 + 错误重试。
- `router.dart`：注册 `/market/orders → OrdersPage`。
- `market_page.dart`：顶栏加「我的订单」入口图标（可发现性，免得又埋深）。
- `voice_assistant_layer.dart`：`_pathFor` `orders → /market/orders`；新增 `_receiverInfo()` 从登录资料组装 `{realName,phone,address}`（地址空返 null）；`show_order_confirm` 读资料拼确认文案、**地址空则引导去「我的-编辑资料」补全**；`create_order` 地址空则拦截提示、否则用资料 receiverInfo 下单。

## 三、契约

- `PUT /user/profile` 多收一个可选 `shippingAddress`；`GET /user/profile` 回显之。
- `create_order` 命令 `receiverInfo` 由必填改可选；App 始终用资料地址填充，地址缺失时 App 侧拦截并引导（不再依赖模型口述地址）。
- 其余订单/支付接口与状态机不变。

## 六、实施备注

- Prisma 加列遇 EPERM：运行中的 `npm run dev`（nodemon→server）持引擎 DLL，`generate` 必失败。停整条 dev 树→generate→重启，DLL 释放即成（见 [[reference-prisma-migrate-nodemon-lock]]）。本段停/重启了 dev 栈，web(:5000 serve_web 独立进程)未受影响。
- 收货信息「App 用资料地址兜底」而非「模型口述」：更稳（demo 不必念地址）、更符合 doc 92「订单确认读 realName/phone/shippingAddress」。代价是后端放宽 receiverInfo 必填——已对应放宽校验与提示词。
