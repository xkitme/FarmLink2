## 6. 测试基础设施策略

### 6.1 每套独立临时 SQLite

每个 Backend characterization 测试套件在 `before` 中创建独立临时目录与 SQLite 数据库：

```
backend/prisma/.test-116d-<suiteName>-<random>/
└── <suiteName>.db
```

已验证模式（参见 `backend/test/auth-session.integration.test.js`）：
```js
import { execFileSync } from 'node:child_process'
import { closeSync, mkdtempSync, openSync, rmSync } from 'node:fs'
import path from 'node:path'

const backendRoot = path.resolve(import.meta.dirname, '..')
const testRoot = mkdtempSync(path.join(backendRoot, 'prisma', '.test-116d-market-'))
// 预创建空 DB 文件（Prisma migrate 要求文件存在）
closeSync(openSync(path.join(testRoot, 'market.db'), 'w'))
process.env.DATABASE_URL = `file:./${path.basename(testRoot)}/market.db`
process.env.APP_ENV = 'dev'

const prismaCli = path.join(backendRoot, 'node_modules', 'prisma', 'build', 'index.js')
execFileSync(process.execPath, [prismaCli, 'migrate', 'deploy', '--schema', 'prisma/schema.prisma'], {
  cwd: backendRoot,
  env: process.env,
  stdio: 'pipe',
})
```

关键约束：
- **数据库文件必须在 `backend/prisma/` 下**，因为 `prisma/schema.prisma` 的相对路径解析以此为基准。
- `DATABASE_URL` 格式 `file:./<相对于prisma目录的路径>/<dbFile>`。
- **禁止使用 `npx`**（会加载 dotenv，从 `.env` 读取正式库路径并覆盖 `DATABASE_URL`）。必须用 `execFileSync(process.execPath, [prismaCli, ...])` 直接调 Prisma CLI，且通过 `env: process.env` 透传已覆写的 `DATABASE_URL`。
- `closeSync(openSync(dbPath, 'w'))` 预创建空文件（Prisma migrate 需要目标文件已存在）。
- 每套件唯一 `mkdtempSync`，不存在并发复用。

### 6.2 Migration Deploy

- `execFileSync(process.execPath, [prismaCli, 'migrate', 'deploy', '--schema', 'prisma/schema.prisma'], { cwd: backendRoot })`（非 `migrate dev`，无交互式 prompt）。
- 依赖 migrations 目录已有完整迁移历史，当前项目满足。

### 6.3 动态 Import

- 测试文件使用 `await import('../src/app.js')`（或 `server.js`）动态加载，确保 PrismaClient 在 `DATABASE_URL` 指向临时库**之后**初始化。
- 动态 import 前必须已完成 `DATABASE_URL` 覆写 + `prisma migrate deploy`。

### 6.4 精确清理策略

| 阶段 | 操作 |
|---|---|
| `before` | `mkdtempSync` → `closeSync(openSync(dbPath,'w'))` → 设置 `DATABASE_URL` / `APP_ENV` → `execFileSync(process.execPath, [prismaCli, 'migrate', 'deploy'])` → 可选 seed（创建测试用户/商品/订单）→ `await import('../src/app.js')` |
| `after` | `try { server?.close?.(); await prisma.$disconnect(); } finally { rmSync(testRoot, { recursive: true, force: true }) }` |
| 约束 | **不** 使用异步 `removeTempDb`（无 `import()` 穿透）；**不** 注册 `process.on('exit')` 广泛兜底（依赖 `try/finally` 确定性清理）；**不** 使用 `tmpdir()`（路径不确定性）；被测应用/Prisma 绝不连接或读写正式库 `backend/data/village.db`（verify-all 仅对正式库做只读 hash/size/mtime 采样用于保护） |

### 6.5 正式库 `village.db` 指纹保护

**硬约束：任何测试不得以任何方式读写 `backend/data/village.db`。**

当前基线指纹（2026-08-07 UTC）：

| 属性 | 值 |
|---|---|
| SHA256 | `FAEECCA0DB422213D71588D1A9B3128CF0E8BBDF45368F93641FCE4F10161E96` |
| Size | `1155072` bytes |
| Mtime (UTC) | `2026-08-07T08:34:59.2995944Z` |

保护措施（`verify-all.ps1` 执行）：

| # | 措施 |
|---|---|
| P1 | 测试启动前计算 `Get-FileHash backend/data/village.db -Algorithm SHA256` + `(Get-Item ...).Length` + `(Get-Item ...).LastWriteTimeUtc` |

| P3 | **任一不一致 → ExitCode 1** 且输出 `"village.db tampered: expected <before> got <after>"`（非 warning，硬失败） |
