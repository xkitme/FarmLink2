### 1. 个人资料完整编辑（`app/lib/pages/profile/settings/account_page.dart`）
- 表单字段扩展为四项可编辑：**昵称 / 真实姓名 / 手机号 / 所属村**；账号、角色保持只读展示。
- 手机号输入限制为纯数字、最长 11 位（`FilteringTextInputFormatter.digitsOnly`），
  保存前本地校验 `^1\d{10}$`（允许留空＝解绑）。
- 输入框统一改为「利落方角小圆角」：`OutlineInputBorder(R.sm=8)` + 描边（聚焦主绿 1.5px），禁胶囊，
  符合设计系统与记忆中的输入框偏好。
- 保存成功后调用 `AuthState.refreshProfile()` 重新拉取并写回本地缓存，页面 `watch` 即时刷新。
- 失败统一走 `actionErrorMessage('保存', e)`。

### 2. 用户模型（`app/lib/models/user.dart`）
- 新增 `realName` 字段，并加入 `fromJson` / `toJson`，使真实姓名能随 `refreshProfile` 落地本地缓存。

### 3. 存储管理真值（`app/lib/pages/profile/settings/storage_page.dart`）
- 从 `ComingSoonPage` 重写为有状态页面，进入即统计真实占用并支持下拉刷新。
- 顶部 Hero 卡展示「本机已用空间」总量与可清理占比进度条。
- 占用明细分三类列出（真实计算，非写死）：
  - **业务数据缓存**：`cache:` / `dashboard:` / `service:` 前缀键，附带缓存记录条数。
  - **待发送队列**：`sync:queue` 键，附带待发送条数（`OfflineSyncQueue.waitingCount()`）。
  - **账号与偏好设置**：其余键（登录信息、提醒开关等）。
- 「清理缓存」走 `useRootNavigator:true` 的底部确认弹窗，确认后移除上述缓存前缀键并 `OfflineSyncQueue.clear()`，
  再重新统计刷新；失败走 `actionErrorMessage('清理', e)`。

### 4. 后端（`backend/src/modules/platform/user.controller.js`）
- `updateProfile` 增加 `phone` 字段支持：留空＝置 null（解绑）；非空校验 `^1\d{10}$` 且校验唯一性
  （已被其他账号绑定时报错）。其余字段（nickname/realName/villageName/regionCode/...）原本已支持。
- **为何需要改后端**：原 `PUT /user/profile` 不接受 `phone`，而任务要求电话可编辑；手机号有唯一约束，
  必须在服务端做唯一性与格式校验，故这是实现需求的最小必要改动。无需新增接口或数据库字段
  （`User.realName` / `User.phone` 在 Prisma schema 中已存在）。

## 用到的接口

- `PUT /user/profile`（既有，扩展支持 phone）：保存昵称/真实姓名/手机号/所属村。
- `GET /user/profile`（既有，经 `AuthState.refreshProfile()`）：保存后刷新真值。
- 无新增接口。

## 存储真值怎么算的

- 数据源：`SharedPreferences` 全量键。逐键累加 **UTF-8 字节数（键名 + 值）** 作为占用估算：
  - String 值直接 `utf8.encode(value).length`；List&lt;String&gt; 逐项累加；其他类型按 `toString()` 估算。
- 按键名前缀归类：`sync:queue` → 待发送队列；`cache:`/`dashboard:`/`service:` → 业务数据缓存；其余 → 账号与偏好。
- 缓存记录条数：对 `cache:*`（排除 `:updatedAt`）的 JSON 数组取 `length` 累加。
- 待发送条数：复用 `OfflineSyncQueue.waitingCount()`（status != synced）。
- 字节转可读单位 `_fmt`：B / KB / MB 自适应。

> 说明：SharedPreferences 实际落盘为平台键值文件，无公开 API 直接读取磁盘占用；以序列化后的 UTF-8 字节数作为占用真值，
> 数值随真实数据增减而变化，区别于此前写死的占位数字。
