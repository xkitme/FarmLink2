## 识图复测

复现失败：

- 旧运行态上传真实叶片图到 `/api/v1/ai/image/detect`，返回 `platform-vision` + `timeout` + `无法识别`。
- 根因不是路由或鉴权，而是视觉模型冷启动超过了后端 30s/60s 预算。

修复后复测：

- 后端重启后，同一张 `app/assets/images/ai_1.jpg` 冷启动识图成功。
- 耗时约 120s。
- 返回：
  - `modelUsed = minicpm-v:8b-2.6-q4_K_M`
  - `resultLabel = 苹果黑星病`
  - `confidence = 0.95`
  - `recognized = true`
  - `knownDisease.modelLabel = apple_scab`
- `/api/ps` 随后显示视觉模型已 warm。

## 仍需注意

3B 已能作为文本主模型运行，但在这台机器上未实测出“3B + vision 同时常驻”。

- `qwen2.5:3b` 实测 `size_vram` 约 2.39GB。
- `minicpm-v:8b` 实测 `size_vram` 约 4.92GB。
- 理论合计约 7.31GB，但即使重启 Ollama 时带 `OLLAMA_MAX_LOADED_MODELS=2` 和 `OLLAMA_KEEP_ALIVE=60m`，先加载 3B 再加载 vision 后，`/api/ps` 仍只保留 vision。
- 结论：当前比赛机/当前 Ollama 运行态仍表现为单模型常驻；3B 能降低文本模型冷加载成本，但不能保证彻底消除文字问答和识图来回切换的模型换入换出。

演示建议：

- 识图现在可用，但首次冷启动仍要按 2-3 分钟预算。
- demo 前先预热当前要演示的模型，识图段和文字段尽量不要频繁交叉。
- 如果要彻底解决来回切换，需要后续继续处理显存/模型/运行时策略，或换显存更大的比赛机。
